# ADR-0026: ベクター描画を自作のキャンバスエディタに置き換える

- **Status**: Accepted
- **Date**: 2026-11-14
- **Deciders**: zredjet
- **Related**: ADR-0004 / ADR-0006 / ADR-0012 / ADR-0017 / ADR-0021 (切替 PR のマージ時点でこの ADR が supersede する)

## Context

ベクター描画 (`vector`) は SVG-Edit 7.4.2 を loopback + sandboxed iframe で同梱している (ADR-0021)。使ってみて、次の 3 点が問題になった。

- iframe の中だけ別のアプリのような UI と古い操作体系で、アプリ本体のデザインやショートカットと合わない
- フレーム (アートボード)、スマートガイド、コンポーネントなど、UI 設計に欲しい機能がない
- loopback サーバ、iframe の隔離、限定 postMessage、ライセンス監査、版の固定と資産契約テストなど、同梱のためだけの仕組みが多い

作りたいものは UI モックアップ、アイコン・ロゴ、バナー・サムネイルで、図解は draw.io (`diagram`) で足りている。SVG-Edit で作った作品のうち、編集を続けたいものはほぼない。

## Decision

### 作るもの

SVG-Edit の同梱をやめ、Figma 風のエディタを自作する。表示名は「キャンバス」にする。draw.io の同梱 (ADR-0017) は変えない。

段階を分けて作る。第 1 段階はモックアップとバナー (フレーム、図形、テキスト、画像、整列、スマートガイド、レイヤーとプロパティのパネル、SVG / PNG 書き出し) で、ここで SVG-Edit から切り替える。第 2 段階はペンツールとパス編集、第 3 段階はコンポーネントとスタイル、第 4 段階はオートレイアウトと制約。各段階の範囲、保存形式、画面、実装の分担は [キャンバスの設計](../canvas-editor-design.md) に置く。

Figma ファイルの読み書き、共同編集、プロトタイピング、プラグイン、任意の外部 SVG の完全な取込、PDF、Illustrator 形式、テキストのアウトライン化は対象外とする。

### モジュールと保存形式

モジュール ID は `vector` のまま変えない。未登録のモジュール ID を持つアイテムはインポートで失敗扱いになるので、ID を消すと古いエクスポートファイルの作品を取り込めなくなり、D-03 に反する。

payload を v2 に上げ、独自のシーン形式にする (ADR-0006)。コアスキーマと JSON export schema は変えない。

- `{ pages, nodes, assets, text }`。`nodes` は ID から引く平たい表で、木の形は `children` が決める。エディタのメモリ上のモデルも同じ形を使う
- 複数ページを持てる形にする。第 1 段階の画面は先頭の 1 ページだけを使う
- 画像は payload の中に base64 で持ち、同じ画像は 1 つのアセットを共有する。別のテーブルは作らない。全アセットの合計は 20 MiB 以下
- 検索用テキスト `text` (1 MiB 以下) は frame の名前、テキストの本文、埋め込み SVG の文字から決まった規則で求める。Rust でも求め直し、一致しない payload を拒否する。`search_preview_field()` は `text` のまま
- すべてのフィールドを必須にし、未知のフィールドを拒否する。コンポーネントやオートレイアウトのためのフィールドは、使う段階で payload のバージョンを上げて足す。先回りして空のフィールドを置かない

v1 の `{ svg, text }` は、`upgrade_payload` で「編集できない埋め込み SVG」1 個の文書に包む。見た目は残り、書き出せる。SVG を図形へ分解する変換はしない。埋め込み SVG は既存の SVG ポリシー (`validate_svg`) で検証し続ける。この書き換えは戻せず、新しい版で開いた作品は古い版のアプリでは読めなくなる (ADR-0006 の通常の挙動)。`data_revision` は増やさない。

### 描画と構造

キャンバスは React から SVG 要素で描く。ノードをいったん SVG 要素の素朴な木にし、画面はそれを React 要素に、SVG 書き出しは同じ木を文字列にする。PNG はその SVG を画像として読み込んで canvas に描く。

モデル、状態、ツール、ヒットテストは DOM に依存させず、描画層と分ける。数千ノードを超えて重くなったら、同じモデルの上に Canvas のレンダラを足す。

エディタの状態はモジュール内の Zustand store 1 つに置く。アプリ全体の状態 (`useAppStore`) には入れず、Context も使わない。保存は明示操作のままにする。表示設定 (ルーラー、グリッドなど) は第 1 段階では永続化しない。

iframe をやめるので、vector 用の loopback サーバ、`mym-vector-v1` の postMessage、エディタ用の CSP はなくなる。外部への通信、外部の script・font の読み込みは引き続き行わない。フォントは同梱せず、その PC のものを使う。

### 依存

エディタのために実行時の依存 (npm、crate) を増やさない。ブーリアン演算のように難しい部分も自作する。どうしても必要になったら、その時点で個別に判断して ADR に残す。

### 移行

- 切替 PR がマージされるまで、`main` で動くのは SVG-Edit で、ADR-0021 の実装と、それを説明するドキュメントの記述が有効である
- それまでの新しいコードは画面 (`src/modules/registry.ts`、`VectorWorkspacePage.tsx`) にもストレージ (`current_payload_version`) にもつながない。途中の `main` はそのままリリースできる
- 切替 PR で、画面の接続、payload v2 の有効化、SVG-Edit 一式の削除、ドキュメントの書き換え、ADR-0021 の Status の更新を同じ変更として行う

## Alternatives

- **新しいモジュール ID を作り、`vector` を画面から外す**: 新しい形式に SVG を持ち込まずに済むが、画面に出ないのにデータ保持とインポートのためだけに残る「引退したモジュール」という扱いを新しく決める必要がある。見えないデータが DB に残り続ける点も避けたい
- **既存の SVG を図形へ変換して編集できるようにする**: SVG-Edit 固有の表現を完全には再現できず、変換の誤りは静かに作品を壊す。編集を続けたい作品がほぼないので、損失のない埋め込みを選んだ
- **Canvas 2D で描く**: 大きな作品に強いが、描画、再描画の制御、ヒットテスト、テスト基盤を自作することになり、第 1 段階が 2〜3 割大きくなる見積もりだった。SVG 書き出しは外せないので、描画の実装が画面用と書き出し用の 2 系統になる点も負担になる。構造を分けておき、必要になってから足す
- **Konva / Fabric などのキャンバス基盤、または tldraw / Excalidraw などの既製エディタを使う**: 早く動くが、土台の作りに縛られてフレームやオートレイアウトを載せにくい。同梱の保守を減らすという目的にも合わない

## Consequences

- loopback サーバ、iframe の隔離、postMessage のブリッジ、SVG-Edit のライセンス監査と資産契約テストがなくなる。portable ZIP は約 1 MB 小さくなる見込み
- エディタ本体はほぼ新規で、第 1 段階だけでテスト込みおおよそ 1 万行の見積もり。操作感 (ドラッグ、スナップ、日本語入力) は自動テストでは確かめきれず、実アプリでの確認が要る
- SVG ポリシーと `validate_svg` は、埋め込み SVG と SVG ファイルの取込のために残る
- 書き出す SVG は取込用のポリシーでは検証しなくなる (埋め込み SVG を `data:image/svg+xml` で持つため)
- フォントを同梱しないので、作ったときと違う PC では文字の幅と折り返しが変わりうる

## Acceptance

- v1 の作品が新しい版で開け、見た目が残り、SVG / PNG に書き出せる
- v1 の `vector` を含む古いエクスポートファイルを取り込める
- アプリ / プロジェクト JSON の入出力とバックアップが v2 で往復する
- macOS / Windows の portable ZIP が各 80,000,000 bytes 以下
- 自動テスト、macOS / Windows 実アプリでの受入を分けて記録する
