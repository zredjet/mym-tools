# キャンバス (自作エディタ) の設計

最終更新: 2026-11-18 / ステータス: v1.0

ADR-0026 と ADR-0028 の決定を実装するための設計。保存形式、エディタ内部の境界、画面、実装の分担を定める。

## 1. 位置づけ

- 対象はモジュール `vector`。表示名は「キャンバス」(ID は `vector` のまま)
- SVG-Edit 同梱 (ADR-0021) を、自作の Figma 風エディタに置き換えた。第 1 段階の切替 (§7) で SVG-Edit 一式を消し、payload v2 を有効にした
- 第 2 段階 (アイコン・ロゴ、ADR-0028) を統合ブランチ `canvas-stage2` で作り、第 2 段階の切替 (§7.5) で `main` に入れた。payload は v3
- エディタは `src/modules/vector/editor/`、画面と IPC の接続は `src/modules/vector/VectorWorkspacePage.tsx` と `canvasIo.ts`、Rust は `src-tauri/src/modules/vector/` にある。`requirements.md` / `ui-design.md` / `data-model.md` / `module-contract.md` / `architecture.md` のキャンバスの記述は本書に合わせてある

## 2. 範囲

### 2.1 用途

UI モックアップ・画面設計、アイコン・ロゴ、バナー・サムネイル。図解は `diagram` (draw.io) の役割で、ここでは扱わない。

### 2.2 段階

| 段階 | 内容 |
|---|---|
| 1 (済み) | モックアップとバナー。この段階で SVG-Edit から切り替えた (§2.3、§7) |
| 2 (済み) | アイコン・ロゴ。回転、ペンツール、パス編集、多角形と星、鉛筆、ブーリアン演算、パスに変換、線のアウトライン化、線の端・角・破線、埋め込み SVG の変換 (§2.4、ADR-0028)。payload v3 |
| 3 | コンポーネントとインスタンス、色・文字のスタイル、ページ切替の画面 |
| 4 | オートレイアウト、制約 |

### 2.3 第 1 段階の機能

- 無限キャンバス、ズーム、パン、ルーラー、ガイド線、グリッド
- ノード: フレーム、グループ、矩形、楕円、線、テキスト、画像、埋め込み SVG (編集不可)
- 表現: 単色とグラデーション (線形・円形) の塗り、単色の線、角丸、不透明度、ドロップシャドウ
- 操作: 選択、範囲選択、移動、リサイズ、複製、削除、グループ化、重なり順、整列、等間隔、フレーム間の移動
- 補助: 整数ピクセルへの丸め、スマートガイド (辺と中心)、ガイド線とグリッドへのスナップ、フレームのプリセット
- パネル: レイヤー (名前変更、表示、ロック、並べ替え)、プロパティ
- Undo / Redo、エディタ内のコピー・切り取り・貼り付け
- 取込: PNG / JPEG / WebP、SVG ファイル (埋め込み SVG として置く)
- 書き出し: SVG、PNG (1 倍・2 倍・3 倍)。対象はフレーム、選択範囲、ページ全体
- 保存は明示操作 (保存ボタンと Cmd/Ctrl+S)。作品は一覧を挟まず直近のものを開く

### 2.4 第 2 段階の機能

- 回転: 箱を持つノードすべて (frame、矩形、楕円、テキスト、画像、埋め込み SVG、パス)。回転のハンドル、角度の欄、15° 刻み (§4.11)
- 左右反転・上下反転 (反転できるノードだけ。§4.11.6)
- パス: ペンツール、点の編集 (点とハンドルの移動、点の追加と削除、角と滑らかの切替、ハンドルの連動の種類、輪郭を閉じる・続ける)、塗りの規則 (§4.12、§4.13)
- 多角形と星のツール、鉛筆 (§4.14)
- ブーリアン演算 (合体・型抜き・交差・中マド)。元の図形を残す (§4.15)
- パスに変換、線のアウトライン化 (§4.16)
- 線の端・角・破線 (§5.3)
- 埋め込み SVG を編集できる形に変換する (§4.17)

結果が §3.5 の上限 (座標、大きさ、ノード数、点の数) を超える操作は、どれも当てずに理由を出す (§5.3 の規則を第 2 段階の操作すべてに当てる)。

### 2.5 入れていないもの

- 第 1 段階から: 画像のフィットと切り抜き、文中の一部だけの書式、複数の塗り、線の内側・外側揃え、矢印、OS のクリップボードとの画像のやり取り、等間隔のスマートガイド、ページ切替の画面、表示設定の永続化
- 第 2 段階で見送ったもの: vector network (点から 3 本以上の線)、パスの点ごとの角丸、傾斜 (skew)、可変幅の線、パスに沿った文字、ブーリアンの子にテキスト・画像・埋め込み SVG・frame・group・線を入れること、パスの単純化、シェイプビルダー、ナイフ

### 2.6 対象外

Figma ファイルの読み書き、共同編集、プロトタイピング、プラグイン、任意の外部 SVG の完全な取込、PDF、Illustrator 形式、テキストのアウトライン化。

## 3. 保存形式 (payload v3)

型は `src/modules/vector/editor/model/types.ts`、上限は `model/limits.json`、検証の合否と変換結果の例は `model/fixtures/payload-v3.json` にある。Rust と TypeScript は同じ JSON を読む。v2 の契約データ `model/fixtures/payload-v2.json` は凍結し、v1 → v2 の段のテストにだけ使う (§3.9)。

v2 は第 1 段階の形式で、v3 はそれに回転、線の端・角・破線、パス、ブーリアンを足したもの (§3.8、ADR-0028)。この節の規則は、断りがなければ v2 と v3 で同じ。

### 3.1 全体

```jsonc
{
  "pages":  [ { "id": "...", "name": "...", "children": ["..."], "guides": [] } ],
  "nodes":  { "<id>": { "id": "<id>", "type": "rect", ... } },
  "assets": { "<id>": { "kind": "image", ... } },
  "text":   "検索用テキスト"
}
```

- `nodes` は ID から引く平たい表。木の形は `pages[].children` と frame / group / ブーリアンの `children` が決める
- 重なり順は `children` の配列の順で、先頭が最背面
- すべてのフィールドは必須。未知のフィールドは拒否する。形式を変えるときは payload のバージョンを上げる (ADR-0006)
- エディタのメモリ上のモデルも同じ形を使い、変換層を持たない

### 3.2 座標

- 単位は px。小数を持てるが、エディタの操作は位置と大きさを整数に丸める (回転、パスの箱、回転したノードのリサイズの例外は §4.11、§4.12)
- ページ直下のノードはページ座標。frame の子は frame の左上 (回転の前の箱の左上) を原点とし、frame と一緒に回る
- group とブーリアンは座標系を作らない。子は自分の親の座標系で持ち、外接矩形は子 (ブーリアンは演算の結果) から求める
- 回転 (v3) は、箱を持つノード (frame、矩形、楕円、テキスト、画像、埋め込み SVG、パス) の `rotation` で持つ。度、時計回りが正 (SVG の `rotate` と同じ向き)、箱の中心 (x + width/2, y + height/2) のまわり。線は端点で、group とブーリアンは子で向きが決まるので持たない。座標の計算は §4.11
- パスの点とハンドルは、ノードの座標系 (箱の左上が原点、回転の前) で持つ (§4.12)

### 3.3 木の規則

- どのノードも、ちょうど 1 つの親 (ページ、frame、group、ブーリアン) の `children` に 1 回だけ現れる
- `children` が指す ID は `nodes` に存在する。`nodes` のキーとノードの `id` は一致する
- group とブーリアンの `children` は 1 個以上。frame は 0 個でもよい
- ブーリアンの子の `type` は `rect` `ellipse` `path` `boolean` のどれか (v3。エディタ側の不変条件は §4.15.1)
- 深さは `maxDepth` 以下 (ページ直下を 1 とする)
- ノード、ページ、アセットの ID は別々の名前空間で、書式はどれも `idPattern`
- `__proto__` は ID に使えない (JavaScript でオブジェクトを表として使うと、この名前だけ正しく扱えないため)

### 3.4 アセット

- `image`: PNG / JPEG / WebP の base64。標準の字母 (`+` `/`) で、パディングは必須、空は不可
- `image` の `mime` と中身の先頭バイトが一致すること (既存の `validate_image` と同じ判定)。PNG は 24 バイト以上でシグネチャが合う、JPEG は 4 バイト以上で `FF D8 FF` から始まる、WebP は 12 バイト以上で `RIFF` から始まり 8〜11 バイト目が `WEBP`
- PNG は IHDR の幅と高さが 1 以上 `maxImageSide` 以下、積が `maxImagePixels` 以下
- `svg`: 既存の SVG ポリシー (`src/modules/vector/policy/policy.json`、`validate_svg`) を通った SVG と、そこから抽出した `text` (v1 と同じ抽出結果と完全に一致すること)
- アセットの `width` / `height` は image も svg も、0 より大きく `maxSize` 以下。画像の実際の大きさと一致するかは確かめない
- アセットはノードから参照されているものだけを持つ。エディタは保存の前に参照されていないアセットを落とす
- 同じ画像を 2 回置いたら、アセットは 1 つを共有する (挿入時に中身を比べる)
- 全アセットの合計 (image の `data` の文字数 + svg の UTF-8 の長さ) は `payloadBytes` 以下
- base64 の判定は 20 MiB の文字列でも正しく動くこと。繰り返しを入れ子にした正規表現を全体に当てると、JavaScript のエンジンによっては数 MiB で誤判定や例外になる

### 3.5 ノードの規則

`types.ts` の型に加えて次を確かめる。数値は有限の JSON number に限る。

| 対象 | 規則 |
|---|---|
| ノードとページの `name` | `maxNameLength` 文字以下。空でもよい |
| `opacity` (ノード、塗り、線、影、停止点) | 0 以上 1 以下 |
| `x` `y` `x1` `y1` `x2` `y2`、ガイド線の `position` | 絶対値が `maxCoordinate` 以下 |
| `width` `height` | 0 以上 `maxSize` 以下 |
| `radius` | 0 以上 `maxRadius` 以下 |
| 色 | `colorPattern` |
| 線の `width` | 0 より大きく `maxStrokeWidth` 以下。線なしは `stroke: null` |
| 影 | `x` `y` は絶対値が `maxShadowOffset` 以下、`blur` は 0 以上 `maxShadowBlur` 以下 |
| グラデーション | 停止点は `minGradientStops`〜`maxGradientStops` 個、`offset` は 0〜1 で昇順 (同値可)。`from` `to` `center` の各成分は絶対値 100 以下、`radius` は 0 より大きく 100 以下 |
| テキスト | `text` は `maxTextLength` 文字以下。`fontFamily` は 1〜`maxFontFamilyLength` 文字で制御文字 (U+0000〜U+001F、U+007F〜U+009F) を含まない。`fontSize` は `minFontSize`〜`maxFontSize`。`fontWeight` は 100〜900 の 100 刻み。`lineHeight` は null か、0 より大きく `maxLineHeight` 以下。`letterSpacing` は絶対値が `maxLetterSpacing` 以下 |
| image / svg ノード | `assetId` が同じ種類のアセットを指す |
| ページ | 1〜`maxPages` 個、ID は重複しない。ガイド線は `maxGuidesPerPage` 本以下 |
| 全体 | ノードは `maxNodes` 個以下。全テキストノードの `text` の合計は UTF-8 で `maxTotalTextBytes` 以下 |
| 文字列 | 対になっていないサロゲートを含まない。Rust の JSON の読み込みが受け付けないので、TypeScript 側の検証で拒否する |
| `rotation` (v3) | -180 以上 180 以下。エディタは -180 より大きく 180 以下にそろえて書く |
| 線の `cap` `join` (v3) | 列挙の値 |
| 線の `dash` (v3) | 0〜`maxDashCount` 個。各値は 0 以上 `maxDashLength` 以下。空でなければ合計が 0 より大きい |
| パスの `subpaths` (v3) | 1〜`maxSubpaths` 個。各輪郭の `points` は 1 個以上。1 つのパスの点の合計は `maxPathPoints` 以下、文書の全パスの点の合計は `maxTotalPathPoints` 以下 |
| パスの点 (v3) | `x` `y` は絶対値が `maxCoordinate` 以下。`in` `out` は null か、各成分の絶対値が `maxCoordinate` 以下 (点とハンドルを別々に確かめ、ハンドルの先 `p + h` は見ない。パネルの上限の判定も同じ) |
| パスの `fillRule`、点の `mirror` (v3) | 列挙の値 |
| パスの箱 (v3) | `width` `height` は 0 以上 `maxSize` 以下 (ほかの箱と同じ)。点が箱に収まっているかは確かめない (エディタが §4.12 のとおり保つ) |
| ブーリアンの `op` (v3) | 列挙の値 |
| ブーリアンの `children` (v3) | 1 個以上。指すノードの `type` は `rect` `ellipse` `path` `boolean` のどれか |

文字数は Unicode のコードポイント数で数える。

v3 で足した上限 (`limits.json`):

| キー | 値 |
|---|---|
| `maxSubpaths` | 1000 |
| `maxPathPoints` | 10000 |
| `maxTotalPathPoints` | 100000 |
| `maxDashCount` | 8 |
| `maxDashLength` | 10000 |

### 3.6 検索用テキスト

文書から次の規則で求め、`text` に入れる。Rust は保存と JSON 取込のたびに求め直し、一致しなければ拒否する (v1 と同じ考え方)。

1. ページを配列の順にたどり、各ページの `children` を配列の順に深さ優先でたどる
2. frame は `name`、text は `text`、svg はアセットの `text` を拾う。group とブーリアンは拾わずに子へ進む (ブーリアンの子は矩形・楕円・パス・ブーリアンなので、拾う文字はない)。ほかのノード (パスを含む) は拾わない。`visible` が false でも拾う
3. 拾った文字列ごとに、空白で区切って空の要素を捨て、半角スペース 1 個でつなぐ。空になったものは捨てる
4. 残ったものを半角スペース 1 個でつなぐ

空白は Unicode の White_Space (Rust の `char::is_whitespace` と同じ集合: U+0009〜U+000D、U+0020、U+0085、U+00A0、U+1680、U+2000〜U+200A、U+2028、U+2029、U+202F、U+205F、U+3000)。JavaScript の `\s` は U+FEFF を含み集合が違うので使わない。

`text` は UTF-8 で `textBytes` 以下。超える文書は保存しない。

### 3.7 v1 から v2 へ

`upgrade_payload(1, { svg, text })` は、v1 の SVG を埋め込み SVG 1 個の文書にする。結果は入力だけで決まる。

- ページは 1 つ (`id: "page1"`、`name: "ページ 1"`、ガイド線なし)
- ノードは 1 つ (`id: "legacy"`、`type: "svg"`、`name: "SVG"`、位置 0,0、表示・ロックなし・不透明度 1)
- アセットは 1 つ (`id: "legacy"`、`svg` と `text` は v1 のまま)
- 大きさは、ルートの `width` / `height` 属性 (数値、`px` 付きも可) が両方とも正ならその値。なければ `viewBox` の幅と高さ。それもなければ 640 × 480。1 以上 `maxSize` 以下に収める
- アセットの `text` は v1 の `text` を使わず、今の SVG の抽出 (Rust の `validate_svg`、SVG ポリシーの抽出) で求め直す。v1 の `text` は書いた時点の抽出の結果なので、抽出の規則が違った作品 (空白の扱いなど) では今の抽出と違うことがあり、そのまま入れると v2 の検証 (アセットの `text` が SVG と一致すること) を通らない。v1 の `text` が無い・文字列でない行も、SVG が読めれば変換する
- 文書の `text` は、変換後の文書から §3.6 の規則で求める。§3.6 の空白の集合は SVG の抽出と違う (U+0085 を空白として扱う) ので、その文字を含む作品ではアセットの `text` と違う値になる。それ以外では同じ値になる

変換の結果は v2 の検証 (Rust と、画面の TypeScript の両方) を通ること (ADR-0027 §2.1)。文字の規則 (XML 1.0 の Char にない文字、U+0085 をそのまま書いたもの) は SVG の文字列のまま当てるので、コメントや CDATA の中の `&#x1;` や U+0085 も拒否する (Rust と TS で同じ結果になり、v1 のまま残って元の SVG を書き出せるので、安全側に倒している)。通らない場合 (今の SVG ポリシーを通らなくなった古い作品など) は変換を失敗として返し、v1 のまま残す。壊れた v2 を書き込まない。v1 のまま残った作品は、保存で上書きされず、画面の「元の SVG を書き出す」(`vector_export_original_svg`) で中身を取り出せる (ADR-0027)。

この書き換えは戻せない (ADR-0006 の通常の挙動)。`data_revision` は増やさない。最初の変換の前に、起動時に `pre-payload-vector-v2` のバックアップを 1 回取った (ADR-0027。版が 2 のアプリ。版が 3 のアプリは §3.9 の `pre-payload-vector-v3` を取る)。

版が 3 の今は、v1 の行を v1 → v2 (v2 の検証) → v3 (v3 の検証) の順に変換する (§3.9)。v1 → v2 の段の規則と結果は上のまま変えない。

### 3.8 v3 で足したもの

| 対象 | v3 で足すもの |
|---|---|
| frame、矩形、楕円、テキスト、画像、埋め込み SVG | `rotation` |
| 線 (`Stroke`) | `cap`、`join`、`dash` |
| 新しいノード | `path`、`boolean` |

```ts
// 回転: 度。時計回りが正 (SVG の rotate と同じ向き)。箱の中心 (x + width/2, y + height/2) のまわりに回す
rotation: number;

export type StrokeCap = "butt" | "round" | "square";
export type StrokeJoin = "miter" | "round" | "bevel";

export interface Stroke {
  color: HexColor;
  opacity: number;
  width: number;
  cap: StrokeCap;
  join: StrokeJoin;
  /** 破線の長さと間隔の並び (px)。空は実線。SVG の stroke-dasharray と同じ意味で、奇数個なら繰り返して偶数にする */
  dash: number[];
}

// FillRule ("nonzero" | "evenodd")、HandleMirror ("none" | "angle" | "angle-length")、PathPoint、Subpath、
// BooleanOp ("union" | "subtract" | "intersect" | "exclude") は model/types.ts

export interface PathNode extends NodeCommon, BoxGeometry {
  type: "path";
  rotation: number;
  /** 1 個以上 */
  subpaths: Subpath[];
  fillRule: FillRule;
  fill: Paint | null;
  stroke: Stroke | null;
  shadow: Shadow | null;
}

/** 子の形を演算した結果を、自分の塗り・線・影で描く。座標系は作らず、外接矩形は結果から求める */
export interface BooleanNode extends NodeCommon {
  type: "boolean";
  op: BooleanOp;
  /** 1 個以上。rect / ellipse / path / boolean だけ。重なり順は配列の順 (先頭が最背面) */
  children: NodeId[];
  fill: Paint | null;
  stroke: Stroke | null;
  shadow: Shadow | null;
}
```

- 点 (`PathPoint`) は `x` `y` と、前後のハンドル `in` `out` (点からの相対。null はハンドルなし)、ハンドルの連動の種類 `mirror` を持つ。輪郭 (`Subpath`) は点の並びと `closed`
- 子を持つノードは frame・group・ブーリアンで、座標系を作るのは frame だけ (§3.2)
- 規則は §3.5 の表の (v3) の行。検索用テキストの規則 (§3.6) は変えない
- 多角形・星・鉛筆、パスに変換、線のアウトライン化の結果は普通のパスで、作り方を覚えるノードはない (ADR-0028)

### 3.9 v2 から v3 へ

`upgrade_payload(2, …)` は、次だけを足した文書を返す。ほかの値と、配列の順 (`pages`、`children`、`guides`、`stops`) は変えない。オブジェクトのキーの順は意味を持たない (Rust の JSON は読み書きでキーを並べ替える)。比べるときは値で比べる。

- frame、矩形、楕円、テキスト、画像、埋め込み SVG に `rotation: 0`
- すべての線 (frame、矩形、楕円、線の `stroke` のうち null でないもの) に `cap: "butt"`、`join: "miter"`、`dash: []`

検証の使い分け (Rust、`src-tauri/src/modules/vector/`):

- v2 の検証 (`scene::validate`) は凍結し、v1 → v2 の段の結果と、`upgrade_payload(2)` の入力を確かめるためだけに使う。v3 の検証は `scene::validate_v3` で、`validate_payload` と `upgrade_payload(2)` の結果に使う。2 つは内部を共有し (`Schema::{V2, V3}`)、写しを 2 つ持たない
- `upgrade_payload(2)` は入力も v2 の検証で確かめる (v3 だけのフィールド `rotation` や `cap` を持つ壊れた v2 の行を、黙って直さないため)
- v1 は v1 → v2 (v2 の検証) → v3 (v3 の検証) の順に変換する。ストレージは段ごとに `upgrade_payload` を呼ぶだけなので、各段の中で自分の結果を検証する
- 結果は v3 の検証 (Rust と、画面の TypeScript の両方) を通ること (ADR-0027 §2.1)

v2 の検証を通る行は、足すだけなので v3 への変換で失敗しない。壊れた v2 の行 (検証を通らないもの) は開けず、ADR-0027 の規則 2 で上書きを拒否する。中身を取り出す専用の口は作らない (JSON エクスポートでは古い版のまま書き出され、`ExportSummary.not_upgraded` で知らせる)。

検索用テキストは変わらないので、`text` はそのまま残す (求め直した値と一致する)。`data_revision` は増やさない。最初の変換の前に、起動時に `pre-payload-vector-v3` のバックアップを 1 回取る (ADR-0027 の規則 1。v1 の行と v2 の行のどちらがあっても取る。版が 2 のアプリで `pre-payload-vector-v2` を取った後でも、v3 のためにもう一度取る)。この書き換えは戻せない。

契約データ:

- `payload-v2.json` は凍結し、Rust の v1 → v2 のテストに使う
- `payload-v3.json` は `payload-v2.json` と同じ形 (`valid` / `invalid` は土台の文書と差分、`upgrade` は `{ name, from, input, v3 }`。`from` は 1 か 2)。v1 → v3 の結果 (v1 → v2 の結果に、埋め込み SVG の `rotation: 0` を足したもの) も入れる。§3 の規則の例 (`payload-v2.json` の invalid に当たるもの) も v3 の土台で持つ。各例に `reason` を書き、invalid の例は規則 1 つだけを破る (検証の順に依存しない)
- 大きな境界の例のために、形を 2 つ広げてある: 差分の `repeat` (`{ op, path, value, count }`。各要素は `value` の複製で、参照を共有しない) と、`valid` を土台 + 差分 (`{ name, reason, base, patch }`、`base` は前の valid の例) で書くもの。TypeScript のテスト (`model/testing.ts` の `fixturePayload` / `applyFixturePatch`) もこれを読む
- Rust の版に依存するテスト (`storage/sqlite.rs`、`commands/backup.rs`、`lib.rs` ほか) は、版の定数から契約データと期待値を選ぶ (`modules/vector/testing.rs` の `CURRENT`、`VectorModuleAt(n)`、`valid_payload(version, name)`、`pre_payload_prefix`)。TypeScript の `PAYLOAD_VERSION` (`model/payload.ts`) と Rust の `CURRENT_PAYLOAD_VERSION` が同じ値であることは TypeScript のテストが `mod.rs` を読んで確かめる

### 4.2 状態

- `state/store.ts` が Zustand の vanilla store を 1 つ作り、`editorStore` と `useEditorStore(selector)` を公開する。契約は `state/types.ts` の `EditorStore`
- これはエディタの中だけの状態で、アプリ全体の状態 (`useAppStore`) には入れない。React の Context も使わない
- 文書の変更は「文書を受け取り、変更後の文書を返す純関数」(`DocRecipe`) で行い、`apply` か `beginGesture` / `updateGesture` / `commitGesture` を通す。変わらないノードは同じオブジェクトを使い回す
- 履歴は文書と選択の組のスナップショットで、上限 100 件。大きな画像の文字列はアセットのオブジェクトごと共有されるので複製されない
- `revision` は文書が変わるたびに増える。呼び出し側は保存した時点の `revision` と比べて未保存かどうかを判定する
- コンポーネントは必要な部分だけを selector で購読し、ノード 1 個の変更で全体を描き直さない
- ジェスチャーの途中で `apply` か `beginGesture` を呼ぶと、先に今のジェスチャーを確定する。途中の `undo` / `redo` はジェスチャーを取り消すだけ
- `cancelGesture` は文書と選択を開始時点へ戻す
- `revision` は `apply`、`commitGesture` (文書が変わったとき)、`undo`、`redo` で 1 増える。`updateGesture` の途中では増えない
- 中身が変わらない操作は、引数の文書そのものを返す。履歴も `revision` も増やさない
- 選択は表示中のページのノードに絞る。消えたノードは選択、ホバー、スコープ、本文の編集中から外す
- `load` は表示位置と表示の設定を残し、ツールを選択に戻す
- 保存は、進行中のジェスチャーを確定してから行う (途中の文書を保存して取り消すと、保存内容と画面がずれる)
- ジェスチャーを閉じるのは、開いた側。パネルの色の選択や本文の編集のように長く開くジェスチャーを、キャンバスは取り消さない (§4.4)

### 4.3 描画

- ノードはまず `SvgEl` (SVG 要素の素朴な木) にする (`render/types.ts` の `BuildNodeSvg`)。画面はそれを React 要素にし、SVG 書き出しは同じ木を文字列にする。描画の規則を 2 か所に書かない
- グラデーション、影 (`feDropShadow`)、切り抜き (`clipPath`) の定義は、使うノードのすぐ隣の `<defs>` に置き、ID は `idPrefix` + ノード ID から作る
- image は `<image>` に data URL で、`preserveAspectRatio="none"`。svg アセットも `<image>` に `data:image/svg+xml;base64,` で置く (文書から隔離され、スクリプトは動かず、ID も衝突しない)
- data URL の組み立ては重いので、アセットのオブジェクトをキーにして結果を使い回す
- テキストは `text/layout.ts` の `layoutText` が返す行を `<tspan>` に置く。`foreignObject` は使わない
- 選択枠、ハンドル、ガイド、作成中の枠は、文書の SVG とは別の重ね描き用の SVG に、ページ座標で描く。太さは倍率に関係なく一定にする
- 本文の編集用の `<textarea>` は SVG の中に置けないので、重ね描きのさらに上の HTML の層に、画面座標で置く
- frame の影は、塗りがあれば塗りの矩形が、なければ線の矩形が落とす。子の形の影にはしない。影は必ず子の背面に描く (線だけの frame でも、影が子の上に重ならない)
- テキストの影のフィルタ領域は、斜体や行の高さからはみ出す字形が欠けないよう、フォントサイズに応じて広げる
- 大きさが 0 の外接矩形にはグラデーションを写せないので、そのときは先頭の停止点の色で塗る
- 大きな画像の data URL を、描き直しのたびに走査しない (エスケープや文字の検査は、利用者が入力した文字列だけに行う)
- 画面外のページ直下のノードは描かない
- 性能の目安は数千ノード。超えて重くなったら Canvas のレンダラを足す。そのために、モデル・状態・ツール・ヒットテストは DOM に依存させない

第 2 段階 (v3) で足した描画:

- 回転したノードは、ノードを描く要素のうち最も外側 (影のフィルタを付けた `<g>` があればそれ) に `transform="rotate(θ cx cy)"` を付ける (cx, cy は箱の中心、親の座標系)。影も形と一緒に回る。frame は自分の子と切り抜きも含めて回す (子は frame の座標系のまま)。回転 0 のときは属性を付けず、v2 と同じ出力にする
- 線の端・角・破線は `stroke-linecap` `stroke-linejoin` `stroke-dasharray` で描く。既定値 (`butt`、`miter`、空) のときは属性を付けない。`stroke-miterlimit` は付けない (SVG の既定の 4)
- パスは `<path d>` 1 つと `fill-rule` で描く。`d` は §4.12 の規則で作る。点が 1 個だけの輪郭は何も描かない。閉じていない輪郭の塗りは、SVG と同じく最後の点から先頭へ閉じた形を塗る
- ブーリアンは、子の形を演算した結果 (`getBooleanResult`、§4.15.3) を `<path d>` 1 つにして、自分の塗り・線・影・不透明度で描く。子を個別には描かない。結果は親の座標系で持つので、`transform` は付けない。結果を求められなかったときは、各子の形をブーリアンの塗りと線でそれぞれ描く (合体に近い見た目。§4.15.3)
- グラデーションを写す箱 (外接矩形を 0〜1 に正規化したもの) は、箱を持つノードでは回転の前の箱で、ノードと一緒に回る。ブーリアンでは結果の外接矩形
- 影のずれ (`x` `y`) はノードの座標系の向きになる (形と一緒に回る)。Figma と違うが、SVG に素直に描ける形を採る。パスとブーリアンの影のフィルタ領域は、線の届く範囲 (`miter` は太さの 2 倍まで) を含めて広げる
- 第 2 段階で足した属性 (パスの `d`、`transform`、`stroke-dasharray`) の数値は、描画と書き出しで同じ関数 (`path/pathData.ts` の `formatPathNumber`) を使い、小数第 4 位で丸めて末尾の 0 を落とす (`-0` は `0`)。v2 からある属性の書き方は変えない (v2 の文書の出力を変えない)

### 4.4 ツール

- `canvas/CanvasView.tsx` が DOM のイベントを `CanvasPointerEvent` / `CanvasKeyEvent` に直し、`tools/registry.ts` の現在のツールへ渡す。ポインターは `setPointerCapture` で追う (HTML5 のドラッグ&ドロップは使わない)
- ツールは store だけを通して文書を変える。ドラッグは `beginGesture` で始め、Esc とフォーカス喪失で `cancelGesture` する
- 作成ツールは 1 回作ったら選択ツールへ戻る
- カーソルは、ふだんはツールの `cursor`。リサイズハンドルの上のように場所で変えたいときは、ツールが `ToolContext.setCursor` で上書きし、null を渡して戻す
- ボタンを押していない移動では、`CanvasPointerEvent.clickCount` は 0 になる
- Space を押している間と中ボタンのドラッグは、どのツールでも手のひらになる。Cmd/Ctrl と一緒の Space では入らない。Space を離したことが届かない場合 (macOS は Cmd を押している間ほかのキーの keyup を送らない) に備え、修飾キーを離したときにも解除する
- ドラッグの途中でホイールやピンチが来て表示位置が変わったら、直前の修飾キーの状態を保ったまま、今のポインター位置での移動をツールへ渡す。手のひらのドラッグは、途中の表示位置の変化を打ち消さない
- `onCancel` は、ドラッグの途中の Esc、ツールの切替、ポインターの取消、ウィンドウからのフォーカス喪失、キャンバスが画面から外れるときに呼ぶ。何もしていないときの Esc は `onKeyDown` へ渡すだけにする
- ツールが `onCancel` で取り消すのは、自分のドラッグが開いたジェスチャーだけ。キャンバスも、ポインターのドラッグの途中だったときにだけ、残ったジェスチャーを取り消す。ドラッグしていないときの Esc、ウィンドウからのフォーカス喪失、キャンバスが画面から外れるときには、開いているジェスチャーに触らない
- 押したまま 4 画面 px を超えて動かした押下 (ドラッグ) は、次の押下をダブルクリックに数えない
- ポインターのドラッグの途中 (ルーラーからガイド線を引き出している間を含む) は、Esc のほかのキーを、ツールにもショートカットにも渡さない。画面の保存と新規のキー (Cmd/Ctrl+S、Cmd/Ctrl+N) も受けない。ドラッグの途中か、と取り消しは、エディタの外から `canvas/pointerDrag.ts` (`isPointerDragActive` / `cancelPointerDrag`、`useCanvasInput` が登録する) で行う。取り消しは Esc と同じで、ツールの `onCancel` を呼ぶ
- ツールが自分のハンドラの中で `setTool` を呼ぶと、その場で自分の `onCancel` が呼ばれる。作成ツールは、先に `commitGesture` と内部状態の片付けを済ませてからツールを切り替える
- OS のファイル選択ダイアログを開くとウィンドウのフォーカスが外れ、現在のツールの `onCancel` が呼ばれる

キーとフォーカスの規則:

- キャンバスのショートカットは、フォーカスがエディタ (`data-canvas-editor` の中) にあるか、どこにもない (body) ときだけ効く。作品バーやサイドバーなどエディタの外にフォーカスがある間と、モーダルが開いている間は、Space や Esc を含めて何も取らない
- 入力欄にフォーカスがある間と、日本語入力の変換中は、文字キーのショートカットを効かせない
- エディタの中のボタンやチェックボックスにフォーカスがある間は、その部品が使うキー (Space、Enter、矢印) を取らない。ほかのショートカットは効く
- キャンバスを押したら、フォーカスをキャンバスへ移す。入力欄にフォーカスがあれば、先にフォーカスを外して入力を確定させてから、ツールへ渡す (選択が変わる前に確定させる)

### 4.5 ヒットテストと選択

ヒットテストは文書の幾何から求める純関数にする (`hit/`)。DOM の `elementFromPoint` には頼らない。

- 前面から順に調べる。`visible` が false か `locked` が true のノードと、その子孫は当たらない
- 塗りのない図形は線の上だけが当たる。線は太さに 4 画面 px の余裕を足す
- ページ直下の frame は、名前のラベルを押したときだけ frame 自身が選ばれる。中の何もない場所を押すと選択を解除し、ドラッグは範囲選択になる
- ページ直下の frame の子は直接選べる。group と入れ子の frame は、まず全体が選ばれ、ダブルクリックで中に入る (`scopeId`)。Esc で 1 段外へ出る
- Cmd/Ctrl を押しながらのクリックは、いちばん深いノードを選ぶ
- Shift を押しながらのクリックは選択に足し、選択済みなら外す
- 範囲選択は、スコープの中で外接矩形が重なるノードを選ぶ。ページ直下の frame は全体が囲まれたときだけ選ぶ
- group のスコープの中では、group の外接矩形の中の何もない場所もスコープの中として扱う (そこから範囲選択ができ、スコープを出ない)
- 祖先と子孫を同時には選ばない。Shift を押しながらのクリックで足すノードの祖先や子孫が選択にあれば、それを外して入れ替える。選択済みの group や入れ子の frame を Shift+クリックしたら、中の子に入れ替えずに外す
- 選択中のノードの上を押したら、選び直さずにドラッグできる。動かさずに離したら、押した位置で選び直す。選択の外接矩形の中の何もない場所からのドラッグは、選択を動かす (ページ直下の frame を選んでいる間は、その中の何もない場所からのドラッグが frame の移動になる)
- 押した位置にあるものの優先順は、リサイズハンドル、ガイド線 (3 画面 px)、frame のラベル、ノード。ダブルクリックはハンドルとガイド線を飛ばす。第 2 段階で、ラベルとノードの間に回転のハンドルが入った (§4.11.3)
- クリックとドラッグは、押してから 3 画面 px 動いたかで区別する。動かないクリックは履歴も `revision` も増やさない。押してから取り消したら (Esc、フォーカス喪失)、選択は押す前に戻る
- ホバーの枠とリサイズハンドルは、選択ツールのときだけ出す

### 4.6 変形とスナップ

- 移動とリサイズの結果は整数に丸める
- 移動: Shift で水平・垂直に固定、Alt で複製。矢印キーは 1 px、Shift と一緒なら 10 px
- 移動の丸めは、動かした向きだけに行う。動かしていない向きの小数の座標は変えない。元の位置へ戻したら文書を変えない
- Alt での複製は、ドラッグが始まった時点 (3 画面 px を越えた時点) の Alt で決める。ノード数の上限で複製できないときは、何も動かさない
- リサイズ: 8 個のハンドル。Shift で縦横比を固定、Alt で中心から。画像と埋め込み SVG だけの選択は既定で縦横比を固定し、Shift で解除する
- 線を 1 本だけ選んだときのハンドルは、始点と終点の 2 個。Shift で 45° 刻み、Alt で中点を固定する
- 画面上で 32 px より小さい選択は、辺の内側をリサイズハンドルにしない (中を押せば動かせる)
- 複数選択と group のリサイズは、子孫の位置と大きさを比例させる。テキストはフォントサイズを変えずに枠だけ変える。角丸と線の太さは変えない
- frame のリサイズは子を動かさない。複数選択や group の中の frame も同じで、frame の枠だけが比例して変わる。変えないのは子の座標の値 (frame の中での位置) なので、左辺や上辺を動かすと、子は frame の左上と一緒に動く
- 複製と貼り付けは、元の位置から右下へ 10 px ずらす
- テキストは、横に引くと `auto-height`、縦にも引くと `fixed` になる。どちらに引いたかは、リサイズ前後の外接矩形の幅と高さの比で決める (結果の数値の差では決めない)。縦に引いていなければ、テキストの `height` と `y` 方向の大きさは丸めでも変えない
- テキストを含むリサイズは、`resizeNodes` のあと、同じ `DocRecipe` の中で `fitTextNodes` (`text/fit.ts`) を通す。幅を変えた `auto-height` のテキストは、折り返した結果の高さになる
- 線の `stroke` は null にできない。複数選択に「線なし」を当てたときは、線だけを対象から外す
- group の解除では、group の不透明度を子に掛け合わせ、group が非表示なら子を非表示に、ロック中なら子をロックにする
- ドロップした位置が別の frame の上なら、その frame の子にする。見た目の位置は変えない。つかんだ点がノードの上なら、ポインターの下の最も前面の frame (なければページ直下) が、つかんだノードの今の親と違うときに付け替える。付け替えるときは、選択のすべてを同じドロップ先へ移す (つかんだノードの親が変わらない間は、親の違うほかのノードも付け替えない)。frame のラベルや、選択の中の何もない場所をつかんだときは、押した点の下の frame と違う frame に入ったときだけ付け替える。Alt での複製では、複製元とその子孫をドロップ先にしない。押した位置へ戻して離したら、親も変えない
- スナップの候補は、同じ親の兄弟と親 frame の辺・中心、ガイド線、グリッド (`snapToGrid` のとき)。6 画面 px 以内でいちばん近いものに吸着し、そろった線を重ね描きする。Cmd/Ctrl を押している間は吸着しない
- ガイド線はルーラーから引き出して作り、ルーラーへ戻すと消える
- 回転したノードと回転した frame の中での移動・リサイズ・回転・反転は §4.11、パスの点の移動は §4.13

### 4.7 テキスト

- 行分割は `text/layout.ts` の `layoutText` が行う。`\n` で改行し、`auto-height` と `fixed` は幅で折り返す。和文は文字の間で、欧文は単語の間で折り返す。行頭に来てはいけない句読点と閉じ括弧の前では折り返さず、直前の文字ごと次の行へ送る (ブラウザの `line-break: strict` と同じ向き。本文の編集中の入力欄と折り返しをそろえるため)
- 行分割の時間は、本文の長さにほぼ比例すること。上限いっぱい (`maxTextLength`) の、空白のない文字列でも固まらない
- 幅は `TextMeasurer` で測る。テストでは固定幅の代用品を渡す。ブラウザでの計測は、SVG の描画と同じ幅を返すこと (空白の並び、絵文字、`system-ui` を含む)。canvas の `measureText` が描画と違う幅を返す場合は、SVG の要素で測る
- 折り返すかどうかの判定に使う幅は、そのエンジンの HTML (本文の編集中の入力欄) が組む幅と描画の幅の広いほうにする (描いた行が枠からはみ出さないことを優先する。WebKit の字間のある絵文字や結合文字、タブは描画のほうが広い)。行の幅、揃えの位置、`auto-width` の大きさは描画の幅で求める。WebKit は HTML を折り返せる単位ごとに組み、単位をまたぐカーニングを入れないので、この 2 つが違う (かなの多い行で最大 1% ほど)。エンジンの違いは、名前ではなく実測で決める
- 描画の `<text>` には `text-rendering="geometricPrecision"` を付け、表示の倍率 (Retina、キャンバスのズーム、UI スケール) に関係なく指定のフォントサイズで組ませる (付けないと、絵文字とシステムフォントの字幅が倍率で変わる)。計測に使う canvas と SVG の要素は `<html>` の直下に置き、文書の言語 (`lang`) を引き継がせ、UI スケール (`body { zoom }`) の影響を受けないようにする
- 字間があるときの描画の幅は、エンジンで組み方が違う。Chromium は文字列全体を組んで書記素ごとに字間を付ける。WebKit の SVG は符号位置ごとに字間を付け、ふつうは 1 文字ずつ並べ (カーニングなし)、異体字セレクタや ZWJ などを含む文字列だけ全体を組む。計測はこれに合わせる。WebKit の編集欄は、字間のある間カーニングを切って描画に近づける
- エンジンで違う折り返しの規則は、編集欄と同じ CSS の要素で確かめて `layoutText` が従う: `/` の後 (WebKit は欧文の前でも折り返す)、`C:\` の `:` の後 (WebKit)、`1-2` の `-` の後 (Chromium)、全角空白を行末にぶら下げるか (Chromium はぶら下げ、WebKit は幅に数える)、収まらない行の末尾の約物を詰めるか (Chromium の `text-spacing-trim`。詰めるかと割合は、フォントと字間と末尾の 2 文字ごとに確かめる。`〛` は詰めない)。単位の途中で割った行は、続く約物との詰め (`、。` の `、`) も残す (Chromium の編集欄がそうする)。行末を詰めた行は、詰めた幅で揃える (編集欄と同じ位置になる)
- 編集欄はタブを次のタブ位置 (`tab-size: 1`) まで進め、描画は空白 1 つとして描く。折り返すかどうかの判定は、編集欄の進め方と描画の広いほうで行う
- 本文の編集欄は、UI スケール (`body { zoom }`) を `zoom` で打ち消して文書のフォントサイズで組み、倍率は `transform` で掛ける。拡大・縮小したフォントサイズで組むと、絵文字とシステムフォントの字幅が変わり、折り返しが描画とずれる
- 本文の編集は、テキストの位置に `<textarea>` を重ねて行う (`text/TextEditOverlay.tsx`)。日本語入力の変換中の Enter と Esc は変換の操作として扱い、編集を終えない
- 編集の開始はダブルクリックか Enter、終了は Esc か外側のクリック。空のまま終えたらノードを消す
- テキストツールは、クリックで `auto-width`、ドラッグで幅を決めた `auto-height` を作る
- フォントは同梱しない。候補 (§5.7) のうち、その PC にあるものを一覧に出し、ほかは名前を直接入力する。あるかどうかは、そのフォントを先頭に置いたときと総称フォントだけのときの幅を比べて判定する (`document.fonts.check` はシステムフォントの有無を返さないので使わない)
- 文書のフォントがその PC になければ、プロパティに注意を出し、総称フォントで描く
- `auto-width` / `auto-height` の大きさは開いたときに求め直す。呼び出し側が `load` に渡す前に求め直すので、履歴にも `revision` にも数えない
- 大きさの求め直しは `text/fit.ts` の `fitTextNodes(doc, ids, measurer)` だけで行う。`auto-width` は幅と高さを、`auto-height` は高さだけを行分割の結果に合わせ、`fixed` は変えない。大きさは切り上げた整数にする。`auto-width` の幅が変わるときは、揃えが左なら左端、中央なら中心、右なら右端を保つ。中央揃えの `x` は丸めない (0.5 刻みになりうる。丸めると、変更を重ねるたびに片側へずれていく)
- 本文、フォント、サイズ、太さ、斜体、行の高さ、字間、大きさの決め方、幅を変える操作は、同じ `DocRecipe` の中で `fitTextNodes` を通す (操作 1 回が履歴 1 件)。変わるものがなければ文書をそのまま返すので、余分に呼んでも履歴は増えない
- 本文の編集の開始と終了は store の `startTextEdit` / `endTextEdit` で行う。選択ツールは、テキストのダブルクリックと Enter で `startTextEdit` を呼ぶ。テキストツールは、作った直後に呼ぶ。終了は `TextEditOverlay` が行う (Esc、入力欄からフォーカスが外れたとき)。ウィンドウからフォーカスが外れただけでは終えない
- 保存は本文の編集を終えない。開いているジェスチャーだけを確定して打った本文を文書に入れ、編集とカーソルの位置はそのまま残す (セッションは、ほかの操作がジェスチャーを確定したら次の入力から新しいジェスチャーにする)。ただし作ったばかりで本文が空のテキストは、保存する文書に入れない。作成のジェスチャーは確定せず (履歴にも `revision` にも入れない)、作る前の文書を保存し、編集は続ける (空のまま終えたら何も残らないのと同じ。`emptyTextCreationBase`)。作成がほかの操作で確定された後のテキストと、既存のテキストを空にした場合は、空のまま保存する (編集を空のまま終えたら、今までどおり削除として履歴 1 件)。日本語入力の変換中の ⌘S は受けない (確定前の文字列を保存しない)
- 画面を離れる前の未保存の確認 (作品の切替、新規、削除、画面の移動、閉じる) は、本文の編集を終えてから行う。そのために、編集をその場で (同期で) 終える関数 (`commitTextEdit`) を `text/` が公開する
- 本文の編集中 (`editingTextId`) のテキストは、文書の層では描かない (入力欄と二重に見えるため)。選択の重ね描きは、編集中のノードにリサイズハンドルを出さない
- 既知の制限: WKWebView は、字間が 0 でないと、SVG の絵文字の並び (ZWJ でつないだもの、肌の色、旗) を分解して描く。入力欄は崩れない。第 1 段階では対応しない

### 4.8 画像と SVG の取込

- ファイル選択 (`plugin-dialog`) と OS からのドロップで受け取り、path を既存の `vector_read_image` / `vector_read_file` に渡す。検証は Rust が行う
- 置く位置は、表示範囲の中央か、ドロップした位置。大きすぎる画像は表示範囲に収まる大きさに縮める (アセットは元のまま)
- SVG ファイルは埋め込み SVG として置く。draw.io の SVG の変換と `notices` の表示は今のまま使う
- 取り込む前に、TypeScript 側の `validateSvg` でも文字を抽出し、Rust が返した `text` と一致することを確かめる。違えば取り込まず、理由を表示する (U+0085 をそのまま含む SVG は Rust とブラウザで抽出が違い、置いても保存できないため)
- 取込は、読み込みが終わった時点でジェスチャーが開いていれば、閉じるのを待ってから置く。読み込みの途中で別の文書が `load` されたら捨てる。本文の編集中なら、編集を終えてから置く

### 4.9 書き出し

- 対象は、選択中の frame やノード、選択がなければページ全体。frame が複数なら 1 つずつファイルにする
- SVG は `SvgEl` を文字列にしたもの。PNG は、その SVG を画像として読み込んで canvas に描く (`src/modules/mermaid/mermaidExporter.ts` と同じ経路)
- PNG の上限は 20 MiB、1 辺 16,384 px、16,777,216 画素 (SVG-Edit の時と同じ)。倍率は 1・2・3
- ファイルへの書き込みは注入された関数を通す。関数は `export/` の中の登録口 (モジュールの変数と設定用の関数) に渡す。登録がない間は、書き出しのボタンを無効にする。アプリの画面は、ファイルごとに保存ダイアログを出して `vector_write_file` で書く関数 (`canvasIo.ts` の `writeExportFiles`) を登録する。2 つ目からは直前に選んだフォルダを既定にし、取り消したらそこで止める。開発用の画面は、ブラウザのダウンロードで保存する関数を登録する
- 書き出す SVG は自分で作った出力なので、取込用の SVG ポリシーでは検証しない (埋め込み SVG を `data:image/svg+xml` で持ち、ルートに `lang`・`xml:lang`・`style` を持つため)。Rust の `vector_write_file` は、SVG が空でなく 28 MiB 以下で、XML として整形式で、XML 1.0 の Char にない文字 (そのまま・文字参照・属性の値) が無く、ルートの要素が SVG の名前空間の `svg` 1 つで、XML 宣言が先頭だけにあることを確かめる (先頭の BOM は許す)
- 埋め込み SVG を含む文書の PNG 書き出しが WKWebView と WebView2 で正しく出るかは、実アプリで確かめる
- 選択が frame だけなら frame ごとに 1 ファイル。frame でないノードを含む選択は全体を 1 ファイル。frame とその中の frame を両方選んだら、外側の 1 ファイルだけにする。非表示のノード (祖先が非表示のものを含む) は書き出さず、書き出し方の判定にも数えない
- frame の範囲は frame の矩形ちょうど (書き出す画像の大きさを frame の大きさと一致させる。線の外側半分は入らない)。それ以外は、影や線の太さを含めた描画の範囲を外側へ整数に丸める
- 入れ子のノードを選んで書き出すときは、位置だけを合わせる。祖先の切り抜きと不透明度は反映しない
- SVG の上限は 28 MiB (埋め込み SVG と画像は base64 で 4/3 倍になる。20 MiB の埋め込み SVG を持つ文書も書き出せる大きさ)。PNG を作る途中の SVG には大きさの上限を当てず、PNG の上限だけを確かめる
- ファイル名の候補は frame・ノード・ページの名前から作る。NFC にそろえ、ファイル名に使えない文字と Windows の予約名を置き換え、同じ書き出しの中で重なれば番号を付ける

### 4.10 コピーと貼り付け

- クリップボードはエディタの中だけで持ち、別の作品へも貼れる。子孫と必要なアセットごと運び、貼るたびに新しい ID を振る
- 貼り付け先は次の順で決める
  1. frame を 1 つだけ選んでいて、それがコピーしたノード自身でなければ、その frame の中
  2. コピー元の親が今の文書にあれば、その親 (コピー元の兄弟になる)
  3. スコープがあればその中、なければページ直下
- 位置は元のページ座標から右下へ 10 px ずらし、続けて貼るたびにさらに 10 px ずらす。貼り付け先の frame の矩形と重ならない位置になるときは、frame の中央に置く
- 複製 (Cmd/Ctrl+D、Alt を押しながらのドラッグ) は、元と同じ親の、元のすぐ前面に入れる。ドラッグでの複製は開始時に 1 回だけ行い、ドラッグの間は同じ複製を動かす
- ブーリアンのスコープの中での貼り付け先は §4.15.1

### 4.11 座標と回転

幾何の基本は `geometry/matrix.ts` (2 × 3 のアフィン行列。SVG の `a`〜`f` の順)。ノードの変換は「親の座標系 ← ノードの座標系」の行列で表す (`model/geometry.ts` の `nodeTransform`)。

- 箱を持つノード: `T(x, y) · R(θ, 中心 = (width/2, height/2))`。ノードの座標系の原点は回転の前の箱の左上
- 線: 恒等 (端点は親の座標系)。group とブーリアン: 恒等 (子は親の座標系)
- ノードからページへの行列は、祖先の frame の行列を順に掛けたもの (`nodePageMatrix`、親の座標系からページへは `coordinateMatrix`)。frame は平行移動と回転だけなので、どの行列も「回転 + 平行移動」になる
- ノードのページ上の角度 φ は、自分の `rotation` と祖先の frame の `rotation` の和 (線・group・ブーリアンは祖先の和。`pageRotation`)
- 座標の行き来は `localToPage` / `pageToLocal` / `localVectorToPage` / `pageVectorToLocal`。第 1 段階の `nodeOrigin` / `parentOrigin` は平行移動の分だけを返すので、回転した frame の中の点には使わない。親の付け替え、グループ化、コピーと貼り付け、移動、書き出しは行列を使う
- 回転と反転のモデルの関数は `model/rotate.ts`、行列での変換とリサイズは `model/transform.ts`

#### 4.11.1 外接矩形

- `getLocalBounds` は、親の座標系での軸に平行な外接矩形を返す。`getPageBounds` は、ページ座標での軸に平行な外接矩形
- 箱を持つノード (楕円とテキストを含む) は、回転した箱の 4 隅を囲む矩形。選択枠に見える箱と同じにする
- パスとブーリアンは、形をその座標系までの行列で写してから曲線の範囲を求める (4 隅を囲むのではない。円を 45° 回しても大きくならない)。ハンドルの先は含めない。ブーリアンの結果が空か求められないときは、子の外接矩形の和
- 選択枠 (複数選択)、スナップの候補、スマートガイド、整列、等間隔、範囲選択、書き出しの範囲、画面外の判定は、この軸に平行な外接矩形で行う
- 回転した箱そのもの (4 隅) は `getNodeCorners(doc, id)` (ページ座標) で返す。1 個だけ選んだ回転したノードの選択枠とハンドルに使う

#### 4.11.2 回転した frame の中

- 親を変えるとき (ドロップ先の付け替え、グループ化と解除、レイヤーパネルの並べ替え、コピーと貼り付け) は、ページ上の見た目を変えない。箱を持つノードは、中心をページ座標で保ち、`rotation` に「元の親のページ上の角度 − 新しい親のページ上の角度」を足す。線は端点、パスは中心を同じように写す (パスの点は変えない)。どちらの座標系も回転していないときだけ、平行移動で済ませる
- 移動: ポインターのずれ (ページ座標) を親の座標系のずれに直して足す。親が回転しているときは、x と y の両方を丸める (§4.6 の「動かした向きだけを丸める」は、親が回転していないときだけ)。Shift の固定は、ページの水平・垂直。矢印キーは、回転した frame の中では frame の軸に沿って動かし、x と y の両方を丸める
- 作成ツール: 回転した frame の中で作るノードは、frame の向きにそろえる (押した点と離した点を frame の座標系に直して箱にする。`rotation` は 0)。テキストツールとペンの点も frame の座標系に直す。回転した親の中の作成はスナップしない
- ドロップ先の判定 (`dropTargetAt`)、テキストの親の判定、ヒットテストは、点を frame の座標系に直してから箱で判定する。範囲選択とスコープの切り抜きの判定は、回転した切り抜きの frame を外接矩形で近似する
- 取込で置く位置の親 (`assets/place.ts` の `containParent`) は、候補の frame ごとに、その frame の向きで置いた箱の 4 隅が frame に収まるかで決める (丸めた後の箱で判定する)。回転した親に置くときは、中心を親の座標系に直してから大きさの半分を引く
- ページ直下の frame の名前のラベルは、回転しても回さず、外接矩形の左上に置く
- 書き出し: frame の書き出しの範囲は、回転を含めた外接矩形。入れ子のノードを書き出すときは、祖先の frame の回転も掛ける (ページ上の見た目のとおり)

#### 4.11.3 回転の操作

- 1 個だけ選んだ箱を持つノード (回転していないノードが回転した frame の中にある場合を含む) は、回転した箱に沿った選択枠とハンドルを出す (`tools/select/selectionBox.ts`)。複数選択、group、ブーリアン、線の選択枠は、軸に平行な外接矩形
- 回転のハンドルは、選択枠の 4 隅のすぐ外 (リサイズのハンドルの外側、隅から 16 画面 px 以内。`ROTATE_HIT`)。カーソルを回転の形にする (15° 刻みの向きの SVG のカーソル)。ドラッグの間、角度を数値で重ね描きする。線 1 本には回転のハンドルを出さない
- 押した位置にあるものの優先順 (§4.5 に足す): リサイズのハンドル (と線の端点) → ガイド線 → frame の名前のラベル → 回転のハンドル → ノード。ラベルは frame の左上の外にあり、回転のハンドルと重なるのでラベルを先にする。ホバーも同じ順
- 回転の中心は、1 個の箱を持つノードなら箱の中心、それ以外は選択の外接矩形の中心
- Shift で、結果の角度を 15° の倍数にそろえる。刻むのはノード自身の `rotation` (パネルと角度の表示と同じ値) で、回転した frame の中でもページ上の角度ではない。複数選択では回した量を 15° 刻みにする。回転の途中はスナップしない
- 回した結果: 箱を持つノードは、中心を回転の中心のまわりに回し、`rotation` に回した量を足す。線は端点を回す。group とブーリアンは子に同じことをする。frame は frame だけを回し、子の値は変えない
- 回転の値は -180 より大きく 180 以下にそろえ、小数第 2 位で丸める。回転だけの操作では、`x` `y` `width` `height` を丸めない

#### 4.11.4 リサイズ

- 回転した 1 個のノードは、回転した箱の向きでリサイズする。動かさない側の辺・角 (Alt なら中心) が、親の座標系で動かないように `x` `y` を決める。丸めるのは `width` `height` だけで、`x` `y` は丸めない (中心まわりの回転なので、整数にそろえると動かさない側がずれる)。このリサイズはスナップしない
- 複数選択と group のリサイズ (§4.6 の比例) で、回転した子は、中心を比例させ、大きさを自分の向きに沿った倍率で変える。幅の倍率は √((sx·cos φ)² + (sy·sin φ)²)、高さは √((sx·sin φ)² + (sy·cos φ)²)。sx, sy は選択の外接矩形 (ページ座標) の横と縦の倍率、φ はノードのページ上の角度。角度は変えない。縦横の倍率が違うと厳密な拡大にはならない (ADR-0028)。回転した子は `width` `height` だけを丸める
- パスは点を変換するので厳密に変わる。複数選択と group では、点とハンドルの先をページ座標で P′ = A + S·(P − A) (A は動かさない点、S は外接矩形の倍率) に写してから、角度を変えずに自分の座標系へ戻し、§4.12 の箱を直す。1 個だけを自分の向きでリサイズするときは、自分の座標系で p′ = a + S·(p − a) (a は動かさない点、S は自分の向きの倍率) にする。線は端点を変換する
- 線の端点のドラッグは、動かした端点だけを丸める (動かしていない端点は元の値のまま。Alt で中点を固定するときは両方)
- テキストの大きさの決め方 (§4.6 の「横に引くと `auto-height`、縦にも引くと `fixed`」) は、テキスト自身の向きでの倍率で判定する。リサイズの後は同じ変更の中で `fitTextNodes` を通す

#### 4.11.5 パネルの位置と大きさ

- 1 個の箱を持つノード: W / H は回転の前の大きさ。X / Y は回転した箱の左上の角 (ノードの座標系の原点を親の座標系へ写した点)。Figma と同じ
- X / Y の入力は、その角が入力した位置に来るようにノードを動かす。W / H の入力は、§4.11.4 の 1 個のリサイズと同じ規則で、左上の角を動かさずに当てる。回転した frame の中の 1 個の箱を持つノードも自分の向きで当てる
- 複数選択、group、ブーリアン、線は、これまでどおり軸に平行な外接矩形 (線は始点と終点)。回転した frame の中では、親の座標系でリサイズする
- 回転の欄は 1 個の箱を持つノードでは自分の `rotation`。複数選択では、全部が同じ値ならその値、違えば「混在」。複数選択への入力は、各ノードを自分の中心のまわりに、入力した角度へそろえる

#### 4.11.6 反転

Shift+H で左右、Shift+V で上下に、選択の外接矩形の中心を通るページの縦 (または横) の軸で映す。

- ノードのページ上の角度 φ は −φ になる。自分の座標系では、左右反転なら x を (`width` − x)、上下反転なら y を (`height` − y) に映す。新しい `rotation` は −φ − (祖先の frame の角度の和) を (-180, 180] にそろえた値
- 位置は、中心を軸で映す (丸めない)
- パス: 点とハンドルを自分の座標系で映す (箱は変わらない)
- 矩形・楕円: 形は対称なので点はない。塗りのグラデーションの `from` `to` `center` を、映す軸の成分だけ 1 − 値にする。影のずれ (`x` か `y`) の符号を変える (パスとブーリアンも同じ)
- 線: 端点を映す。group とブーリアン: 子に同じことをする。ブーリアンの塗りのグラデーションと影も映すが、これらは親の座標系の向きなので、祖先の frame の角度が 90° の倍数でなければ近似になる
- テキスト、画像、埋め込み SVG、frame は鏡像を表せないので、これらを (子孫に) 含む選択では反転できない (ボタンとショートカットが効かない)

#### 4.11.7 テキスト

- 回転したテキストは、本文の編集用の `<textarea>` も同じ角度で回す (CSS の `transform`。ページ上の角度 φ)。第 1 段階の編集欄の形 (`editorStyle`) を回転した箱の左上の角に置き、余白のずれも回し、`transform` の先頭に `rotate(φdeg)` を足す。回転していなければ第 1 段階と同じ
- 大きさを求め直して幅や高さが変わるとき (`fitTextNodes`) は、§4.7 の揃えで保つ辺 (左・中央・右) と上の辺が、回転していても親の座標系で動かないように `x` `y` を決める。`x` `y` は丸めない

#### 4.11.8 ヒットテスト

- 箱を持つノードは、点をノードの座標系へ戻してから箱で判定する
- パス: 塗りがあれば、塗りの規則で内側を判定する (曲線を折れ線にして求めてよい。誤差は 0.25 画面 px 以内)。線があれば、線までの距離が (太さ + 4 画面 px) の半分以内。どちらもなければ、輪郭までの距離が 2 画面 px 以内。第 1 段階の矩形・楕円・線と同じ余裕 (§4.5 の `STROKE_HIT_SLOP`、太さに 4 画面 px を足した帯) なので、パスに変換しても当たりは変わらない
- ブーリアン: 結果の形で、パスと同じ規則。ブーリアンの中 (スコープ) では子を個別に選べる。子は形の内側と、輪郭から 2 画面 px 以内で当たる (`hitTestPath` にスコープを渡す。型抜きの抜く側の子もスコープの中で押せる)。スコープの外では、深いクリックはポインターの下の子で止まる
- 矩形の角丸の当たりは、描画と同じ角 (§4.12 の角丸) にする

### 4.12 パスの形

- 点の座標とハンドルは、ノードの座標系 (箱の左上が原点、回転の前) で持つ。ハンドルは点からの相対
- 箱は形にぴったり合わせる: 曲線の範囲 (ハンドルの先は含めない) の左上が (0, 0)、大きさが `width` × `height`。形を変える操作のあとは、同じ `DocRecipe` の中で `fitPathNodes(doc, ids)` (`path/fit.ts`) を通す。範囲がずれていたら点を平行移動して箱を合わせ、見た目が動かないように (回転していても) `x` `y` を決める。範囲の差が 1e-6 以下なら直さない。変わるものがなければ文書をそのまま返す。新しいパス (`createPath`) も同じ規則で箱を合わせる
- ツールの操作で入る点とハンドル (ポインターの位置から決まるもの) は、画面上で区別できない桁を持ち込まないよう、親の座標系で小数第 2 位に丸めてから入れる。`fitPathNodes` の平行移動と、変換を掛けた結果は丸めない
- 箱の `x` `y` `width` `height` は、曲線の範囲なので小数になる。移動の丸め (§4.6) は、パスでは箱に対して行う
- `d` の作り方: 輪郭ごとに `M`、点と点の間は、前の点の `out` と次の点の `in` がどちらも null なら `L`、そうでなければ `C` (null の側は点そのものを制御点にする)。閉じた輪郭は最後の点から先頭の点への線分 (または曲線) を描いてから `Z`。点には平行移動 (箱の `x` `y`) だけを掛けて書き、回転は `transform` で付ける。`d` の読み込み (`parsePathData`) は円弧 `A` を含むすべての命令を受け、円弧は 90° 以下の 3 次ベジェで近似する
- 矩形 (角丸を含む)、楕円、線は、同じ点の形 (`Subpath[]`) にできる (`path/shapes.ts`)。描画と同じ形にする。幅か高さが 0 なら形は空 (`[]`) で、空の `subpaths` は検証を通らないので、そのような結果は当てない:
  - 角丸は、描画 (`rx` だけを付ける) と同じく SVG の規則に従う: rx = min(角丸, width/2)、ry = min(角丸, height/2) の楕円の角
  - 始点と向きは SVG 2 の `rect` と `ellipse` の等価なパスと同じ (矩形は (x + rx, y) から、楕円は (cx + rx, cy) から、どちらも時計回り)。線は始点から終点。破線の位置が変わらないようにするため
  - 楕円は 4 本の 3 次ベジェ (κ = 0.5522847498)

### 4.13 ペンと点の編集

#### 4.13.1 状態とツール

- store の `editingPathId: NodeId | null` と `startPathEdit(id)` / `endPathEdit()`。本文の編集と同時には開かない。入るときは `path/editSession.ts` の `beginPathEdit(store, id)` を使う (前の点の選択とペンの描きかけを片付けてから `startPathEdit` を呼ぶ)
- 点の編集は、専用のツール `pathEdit` (ツールバーには出さない) が受ける。`startPathEdit` は `editingPathId` を決めてツールを `pathEdit` にし、`endPathEdit` は選択ツールへ戻す。点の押下・ドラッグ・範囲選択・ダブルクリック・キーは `tools/pathEditTool.ts`、点とハンドルの重ね描きは `tools/pathEdit/PathEditOverlay.tsx` (ペンと共用)、純関数は `tools/pathEdit/ops.ts` と `pen.ts`。キーは、ツールの `onKeyDown` がショートカットより先に受ける (§4.4)
- 点の編集中にペン (P) へ切り替えたときだけ、`editingPathId` を残す (ペンで同じパスに輪郭を足すため)。ほかのツールへの切替、選択の変更、ノードの削除、`load` で編集を終える
- Undo / Redo は、編集中のパスが残っていれば点の編集を続ける (選んでいる点は外し、選択はそのパスにする)。消えたら終える
- 選んでいる点、ペンの描きかけの状態などは `path/editSession.ts` に持ち、store には入れない。パネルが読むための購読の口 (`subscribePathEdit(listener)` / `getPathEditSnapshot()` / `usePathEditSnapshot()`) を置く。選んだ点は、選んだときのパスの `subpaths` のオブジェクトが同じ間だけ有効 (ほかの操作で形が変わったら空になる)
- 点の編集の操作 1 回 (点のドラッグ、ハンドルのドラッグ、点の追加・削除、ペンの 1 点) が履歴 1 件。ジェスチャーは自分で開いて閉じる (§4.4)
- 点の編集中は、そのパスの選択枠・外接矩形・リサイズのハンドルを出さない (点の重ね描きだけ)

#### 4.13.2 入る・出る

- パスを選んで Enter、またはパスをダブルクリックで入る (`tools/select/actions.ts` の Enter と `tools/selectTool.ts` のダブルクリックから `beginPathEdit` を呼ぶ)。矩形・楕円・線・ブーリアンは入らない (先に「パスに変換」する。ブーリアンの Enter は中に入る)
- Enter、Esc (操作の途中でなければ)、パスの外のクリック (ドラッグなし) で出る。外のクリックがほかのノードの上なら、そのノードを選ぶ
- Esc の順は、操作の取消 → 点の編集の終了 → 本文の編集の終了 → スコープを 1 段外へ → 選択の解除

#### 4.13.3 点の編集の中

- 点を押すと選ぶ (Shift で足す・外す)。何もない場所からのドラッグで範囲選択。Cmd/Ctrl+A ですべての点
- 線分を 1 回クリックすると、両端の点を選ぶ (そのまま線分をドラッグできる)
- 選んだ点のドラッグで、ハンドルと一緒に動かす。結果の位置は親の座標系で小数第 2 位に丸める。矢印キーで 1 px、Shift と一緒なら 10 px (ページ座標の向き)。矢印キーの移動量は丸めない (回転した frame の中で 45° のときも、Shift+← を 30 回で −300 px ちょうど)。スナップは §4.6 と同じ候補に、同じパスのほかの点を足す
- ハンドルのドラッグで曲線を変える。`mirror` が `angle` なら反対のハンドルの向きを、`angle-length` なら向きと長さをそろえる。Alt を押しながらのドラッグは、その点の `mirror` を `none` にする
- 点のダブルクリックで、角 (ハンドルなし、`none`) と滑らか (前後の点から求めたハンドル、`angle-length`) を切り替える
- Cmd/Ctrl を押しながら点をドラッグすると、ハンドルを引き出す (角を滑らかにする)
- 線分のダブルクリックで、そこに点を足す (曲線の形を変えずに分ける。`path/edit.ts` の `insertPointAt` は新しい点と前後の点だけを変える)
- Delete / Backspace で選んだ点を消し、前後をつなぐ。点がなくなった輪郭は消し、輪郭がなくなったパスはノードごと消す (編集も終える)
- ノードに対する編集のショートカット (コピー、切り取り、貼り付け、複製、グループ化、重なり順、反転、パスに変換、ブーリアン、線のアウトライン化) は効かせない (`isBlockedInPathEdit`)。Cmd/Ctrl なしの Alt+Shift は、キーの文字に関係なく止める (macOS の Option のデッドキーを含む)。Undo / Redo と保存は効く。ノードの編集のショートカットを足すときは、ここにも足す
- 選んだ点の X / Y (親の座標系で表示) と `mirror` は、プロパティパネルの「点」の節に出す (§5.3)

#### 4.13.4 ペン (P)

- クリックで角の点、ドラッグで滑らかな点 (ドラッグの向きと長さが `out`、`in` はその反対、`angle-length`) を足す
- Shift で、前の点から見て 45° 刻みに固定する (ページの向き)
- 描き始めの点をクリックすると輪郭を閉じ、描くのを終える。最後に置いた点をもう一度クリックすると、開いたまま終える。Enter と Esc でも開いたまま終える。描いている間の Backspace は最後の点を消す
- 最初の点だけではパスを作らず、履歴にも入れない (点は描きかけの状態にだけ持つ)。2 点目でパスを作る。最初の点だけのときの Cmd/Ctrl+Z は、その点を取り消す (文書の Undo はしない。Shift+Cmd/Ctrl+Z は文書の Redo へ渡す)
- Undo でペンが作ったパスが消えると、「最初の点だけ」の描きかけに戻る。パスの ID は覚えておき、Redo でパスが戻ったら同じパスに続けて描く (二重に作らない)
- 作ったばかりのパスで Backspace を押したとき、文書がペンの確定したままなら、Undo で作成を取り消す (履歴を残さない)。ほかの変更があれば、点を消す変更として当てる
- 描きかけは、ツールの切替で終える。ウィンドウのフォーカス喪失、ポインターの取消、キャンバスが画面から外れるとき (ツールがペンのまま) は、押している途中のものだけを取り消して描きかけを続ける (最初の点を置いた押下なら、その点を捨てる)。点の編集の中で始めた描きかけは、編集中のパスが変わったら終える
- 点の編集の中でペンを使うと、同じパスに輪郭を足す。開いた輪郭の端の点から始めると、その輪郭を続ける。線分をクリックすると点を足す
- 何も編集していないときのペンは、新しいパスを作る。親は作成ツールと同じ決め方 (§4.6 のドロップ先、スコープ、§4.11.2、ブーリアンのスコープでは §4.15.1)。塗りなし、線は `createStroke()` の既定 (黒、太さ 1)、名前は「パス」
- 描き終えたら、選択ツールに戻って作ったパスを選ぶ (§4.4 の作成ツールと同じ)。点の編集の中からペンを使ったときは、`pathEdit` に戻って点の編集を続ける
- 描いている間は、最後の点からポインターまでの予定の線を重ね描きする

### 4.14 多角形・星・鉛筆

- 多角形と星はドラッグした矩形に収まる形を作る。Shift で正方形、Alt で中心から。頂点の数は多角形が既定 3、星が既定 5、3〜60。星の凹み (内側の半径 ÷ 外側の半径) は既定 0.382、0.01〜1
- 頂点の数と凹みは、ツールを選んでいる間にプロパティパネルの「ツールの設定」の節で変える (ドラッグの途中のキーはツールに渡らないので、↑ / ↓ では変えない。§4.4)。凹みの欄は % (1〜100、小数第 1 位) で見せる。値はエディタを開いている間だけ覚える (プロパティパネルの「ツールの設定」の節が作られたとき、つまりエディタを開いたときに既定へ戻す)
- 形は、最初の頂点を上の中央に置いた正多角形 (星は外側と内側の頂点を交互) を作り、ドラッグした矩形にぴったり収まるよう縦横に拡大する (点は小数第 2 位に丸める)。結果は角の点だけの閉じたパスで、名前は「多角形」「星」、塗りと線は矩形ツールの既定
- 多角形と星のツールは、矩形ツールのドラッグ (`createDragTool("rect")`) をそのまま使い、入った矩形を同じ ID・箱・見た目のパスに差し替える (`tools/polygonTool.ts`)。矩形ツールが `apply` / `updateGesture` で入れることに依存しているので、作成ツールにノードを作る関数を渡せる口ができたら置き換える
- 鉛筆 (Shift+P) はなぞった点を集め、3 次ベジェに当てはめて (`pencil/fit.ts` の `fitCurve`。誤差 2 画面 px、`PENCIL_TOLERANCE`) 開いたパスを作る。塗りなし、線は `createStroke()` の既定、名前は「鉛筆」
  - 押してから 3 画面 px 動いたら描き始める。描いている間は、なぞった折れ線 (2000 点に間引く) をそのままパスとして見せ、離したときに当てはめる
  - 閉じるのは、なぞりの途中で始点から 16 画面 px 以上離れ (`CLOSE_LEAVE_FACTOR` × 8)、終点が始点から 8 画面 px 以内 (`PENCIL_CLOSE_DISTANCE`) に戻ったときだけ (短いなぞりは開いたまま)。閉じるには 3 点以上が要る。閉じた当てはめが曲線 1 本になったら t = 0.5 で分ける (点 1 個の輪郭にしない)
  - 70° を超えて曲がる所 (`CORNER_ANGLE`。誤差の 3 倍以上離れた前後の点で測る、最大 50 点) を角の点 (`mirror: "none"`) にして、その間を当てはめる。ほかの内側の点は `angle`、端と閉じた輪郭の始点は `none`
  - 誤差はサンプルの点に加えて、サンプルとサンプルの間の中点でも確かめる。保存するときの丸め (小数第 2 位) の分を許容から引いて (max(許容 − 0.01, 許容 / 2)) 当てはめる
  - 点の数が上限 (§3.5) を超えるときは、許容を 2 倍にして最大 10 回当てはめ直し、それでも収まらなければ作らない
- 3 つとも、作ったら選択ツールに戻る (§4.4)。回転した frame の中では frame の座標系で作る (§4.11.2)

### 4.15 ブーリアン演算

#### 4.15.1 木の規則

- 不変条件: ブーリアンの子は 1 個以上で、種類は `rect` `ellipse` `path` `boolean` だけ。木を変える関数 (挿入、断片の挿入、親の付け替え、グループ化、削除、複製、貼り付け、レイヤーパネルの並べ替え) はすべてこれを守る。子のない group とブーリアンは挿入しない
- 子がなくなったブーリアンは、空の group と同じく消す (`removeEmptyGroups` の対象に入れる)
- 「座標系を作らない入れ物」(group とブーリアン) の判定は 1 つの述語 `isGroupLike` (`model/tree.ts`) で行う。子を持つかは `isContainer` (frame・group・ブーリアン)。子にできるかは `canBeBooleanChild` / `canHaveChildOfType`、子にできない種類を入れるときの親は `insertionParent` / `outsideBooleans` で、ブーリアンの外へ出る。`isBoxNode` はブーリアンを箱なしと判定する
- ブーリアンのスコープの中での操作:
  - 複製と、子にできる種類だけの貼り付けは、ブーリアンの中に置く
  - 子にできない種類を含む貼り付け、作成ツール、ペン、取込は、ブーリアンの親に置く
  - グループ化はできない (効かない)。線のアウトライン化は、ブーリアンの子には効かない (子の線は描かないため)。パスに変換は効く (子のまま、パスに変わる)
- 子にするのは、ブーリアンを作る操作、複製・貼り付け (上のとおり)、レイヤーパネルの並べ替え (子にできる種類だけ。子にできない種類は、ブーリアンの中にも子の間にも落とせない) だけ

#### 4.15.2 意味

- 子を配列の順に演算する。合体 (`union`) はどれかに含まれる面、交差 (`intersect`) はすべてに含まれる面、中マド (`exclude`) は奇数個に含まれる面、型抜き (`subtract`) は表示されている子のうち最背面のものから、残りの合体を引いた面
- 子の形: 矩形・楕円・パスは §4.12 の点の形に、ノードの変換を掛けて親の座標系にしたもの。パスは自分の `fillRule` で面を決め、閉じていない輪郭は閉じた形として扱う。ブーリアンの子は、その結果 (`nonzero`)
- 子の塗り・線・影・不透明度は描かない (データは残す)。非表示の子は演算に入れない。表示されている子がなければ結果は空
- 結果は閉じた輪郭の並びで、`nonzero` で塗ると正しい面になる (巻き数はどこでも 0 か 1)。外側の輪郭は時計回り、穴は反時計回り (y が下向きの座標で)。面がなければ空。点で接する面と、外側の輪郭に点で接する穴は、別の輪郭になる。面積のない形 (線、大きさ 0) は面を作らない

#### 4.15.3 計算

- `boolean/index.ts` の `booleanOperation(op, operands)`: 純関数で、同じ入力には同じ結果を返す
  - 曲線同士の交点を求めて分け (`geometry/intersect.ts`)、各部分の両側の巻き数から残す部分を選び、つなぎ直す (paper.js と同じ考え方)。重なった辺、接する曲線、自己交差、同じ点を通る複数の輪郭を扱う
  - 結果の曲線は入力の曲線の一部 (折れ線に近似しない)。同じ入力の曲線の続いた部分は 1 本に戻す
  - アイコンの大きさ (曲線 200 本ほど) で 1 回 5 ms 以内 (実測: 歯車のアイコン 198 本で 1.1〜1.6 ms、Apple Silicon の Node)
  - 求められなかったときは `null` を返し、例外を投げない
  - 1 つのオペランドの合体は、その形を正規化する (向き、自己交差、重なり)。パスに変換に使う
- `null` になるのは: 交点が求めきれない (曲線の組の上限に当たった)、座標の絶対値が 1e15 を超える、面積があるのに小さすぎる輪郭がある (大きさが 100 × 交点のまとめの幅未満。ふつうの座標で 1.28e-3 px、1e6 付近で 1.28 px。幅のない小さな輪郭は捨てる)、ほぼ一直線に重なる曲線で両側の巻き数が決まらない、内部の整合の確かめに失敗した、有限でない座標
- 許容は `toleranceFor(座標の最大の絶対値)` (= max(1e-7, 値 × 1e-10))。交点のまとめは 8 倍、重なりのまとめは 128 倍
- `boolean/result.ts` の `getBooleanResult(doc, id)`: 文書の中のブーリアンの結果 (`{ subpaths, bounds } | null`、親の座標系) を返す。子の形を集めて `booleanOperation` を呼ぶ。ブーリアンのノードと子孫のノードのオブジェクトが同じなら、前の結果を使い回す (`WeakMap`)。描画、外接矩形、ヒットテスト、パスに変換、線のアウトライン化は、どれもこれを通す。入れ子のブーリアンの結果が `null` なら、外側も `null`
- 結果が `null` のとき: 描画は子の形をブーリアンの塗りと線でそれぞれ重ねて描き (合体に近い見た目)、レイヤーパネルのその行に注意を出す。外接矩形は子の外接矩形の和。パスに変換と線のアウトライン化は当てずに理由を出す

#### 4.15.4 操作

- 2 個以上の矩形・楕円・パス・ブーリアンを、同じ親の中で選んでいるときに作れる (Alt+Shift+U / S / I / E、「変換」の節のボタン)。選んだノードを、選択の中で最も前面のものの位置に置いたブーリアンに入れる。子の順は元の重なり順
- 新しいブーリアンの塗り・線・影は、最背面の子のものを写す。不透明度は 1、表示、ロックなし。名前は「合体」「型抜き」「交差」「中マド」
- ブーリアンの節で演算を切り替えられる (履歴 1 件)。名前が既定の名前のままなら、新しい演算の名前に変える
- ダブルクリックか Enter で中に入り (スコープ)、子を選んで動かせる。動かしている間も結果を描き直す。中では子の輪郭を重ね描きする
- グループの解除 (Shift+Cmd/Ctrl+G) で、子を親へ戻す。不透明度・非表示・ロックは group の解除と同じく子へ写す (§4.6)。子は自分の塗りで描かれるようになる
- 「パスに変換」で、結果を 1 つのパスにする (§4.16)

### 4.16 パスに変換と線のアウトライン化

パスに変換 (Cmd/Ctrl+E、`path/flatten.ts`):

- 矩形、楕円、線、パス、ブーリアンを、同じ見た目のパスにする。テキスト、画像、埋め込み SVG、frame、group を含む選択では効かない
- 1 個なら、ID・名前・表示・ロック・不透明度・塗り・線・影と、箱を持つノードなら回転を引き継ぐ。形は §4.12 の点の形 (始点と向きも同じなので、破線の位置も変わらない)。線は塗りなしの開いた輪郭 1 本。ブーリアンは結果の形 (回転 0)。パスは何もしない。大きさ 0 の矩形・楕円と、結果が空のブーリアンは当てずに理由を出す
- 複数なら、同じ親の中で選んでいるときだけ、1 つのパスにまとめる (Figma と同じ)。結果は新しい ID で、選択の中で最も前面のものの位置に置く。最背面のノードの名前と見た目 (塗り・線・影・不透明度) を引き継ぎ、表示・ロックなしにする。回転は点に焼き込んで回転 0 にする。輪郭は重なり順に並べる。塗りのある形は、それぞれ `booleanOperation("union", [その形])` で向きをそろえた輪郭にしてから並べ、`nonzero` で塗る (重なった所が穴にならない)。塗りのない形は輪郭をそのまま並べる。そのため、塗りのある形の線の見た目 (破線の位置、開いた輪郭の閉じる辺、自己交差の内側の線) は変わりうる。合体が求められない形があれば当てない
- ブーリアンの中で複数の子をまとめるときは、子の塗りの有無に関係なく、各子を自分の塗りの規則で合体してから並べる (ブーリアンは子の塗りを描かないため。面積のない子は落とす)。交差・中マドのブーリアンでは、子をまとめると演算の入力が減るので結果が変わる (Figma と同じ)
- 非表示のノードはまとめに入れず、その場に残す (ブーリアンの中でも外でも)。全部が非表示なら当てずに理由を出す (`allHidden`)
- 結果が上限を超えるとき、ブーリアンの結果が求められないときは当てない

線のアウトライン化 (Shift+Cmd/Ctrl+O、`outline/`):

- 線のある矩形・楕円・線・パス・ブーリアンの線を、線の見た目どおりの塗りの面にする。塗りの色と不透明度は線のもの (単色)、線はなし。非表示・ロック中のノードも変換し、状態は引き継ぐ
- 塗りもあるノードは、元のノードの ID・名前・表示・ロック・不透明度の group にし、中に塗りの形 (名前「塗り」、線なしのパス。パスに変換と同じく箱と回転を保ち、影もここに付ける) と線の面 (名前「線」、回転 0) を入れる。group は影を持てないので、影は塗りの形だけが落とし、線の外側半分の影は消える。塗りの不透明度が低いと影も薄くなる (既知の近似)
- 線だけのノードは、線の面のパス 1 つにする (回転 0。影のずれは回転を焼き込んだ向きにする)
- ブーリアンの子には効かない (§4.15.1。操作も出さない)
- 計算は `outline/index.ts` の `outlineStroke`。描画と同じ規則 (端、角、`miter` の上限 4、破線は始点から。始点と向きは §4.12) で、重なった部分は `booleanOperation` の合体で 1 つの面にする。誤差は、線の太さの 1% と 0.05 px の大きい方以内
- 描画のエンジンで違う所は WebKit (macOS の WKWebView) に合わせる: 閉じた輪郭の破線は、最後の破線が終わりまで続いても始点で先頭の破線と角でつながない (Chromium = Windows の WebView2 はつなぐので、始点の角の見た目が違う)。長さ 0 の破線の四角い端は道の向き、ちょうどの尖点は平ら。長さ 0 の輪郭の点は実線のときだけ端の形を描く。破線の位置は曲線の厳密な長さで決める (Skia の近似とは長い曲線の終わりで 0.1〜0.3 px ずれる)
- 回転したノードは、点に回転を焼き込んで計算し、線の面の回転は 0
- 複数を選んだときは、ノードごとに当てる。何も描かないノードは飛ばし、1 つも当てられなければ理由を出す (`empty`)
- 計算が重すぎる形は断る (`tooComplex`): 部分の数 20,000、破線の区間 5,000、合体に渡す線分 60,000、範囲が重なる線分の組 60,000 (数えるのも 3,000 万組で打ち切る) を超えるとき。1 回目の合体が 300 ms を超えたら、別の詰め方での求め直しをしない
- 結果が上限を超えるとき、計算できないとき (`failed`) は当てない

### 4.17 埋め込み SVG の変換

- 埋め込み SVG を 1 個選んでいるとき、「変換」の節の「編集できる形に変換」で行う。`svgconvert/convert.ts` の `convertSvg` が、アセットの SVG (ポリシーを通ったもの) を読み、group・パス・矩形・楕円・線・テキストの断片 (`model/fragment.ts` の `Fragment`。埋め込み SVG のノードの座標系、回転の前) と、落とすもの・近似になるものの一覧を返す。`svgconvert/place.ts` が、断片をノードのページ上の行列で写して置き換える
- 見た目の基準は今の描画 (`<image preserveAspectRatio="none">` で箱に引き伸ばしたもの)。ルートの `viewBox` から箱への変換を、すべての形に掛ける。`viewBox` がなければ、ルートの `width` / `height` (なければアセットの `width` / `height`) を座標系として箱へ引き伸ばす (エンジンによって描き方が違いうる)。ルートの `transform` は読まない
- 対応: `g` と `a` は group (子が 1 個なら group を作らない。作らないときは `<title>` を子に渡す)、`path`・`polyline`・`polygon` はパス、`rect` は矩形 (`rx` と `ry` が違えばパス)、`circle`・`ellipse` は楕円、`line` は線、`text`・`tspan` はテキスト (位置を指定した `tspan` ごとに 1 行、`auto-width`。ベースラインを合わせるが近似。`dx` `dy` は最初の値だけ読む)、`use` と `symbol` は展開する。入れ子の `svg` は、自分の `viewBox` の変換を掛けた group にする (切り抜きは、中身が枠をはみ出すときだけ一覧に出す。`use` → `symbol` も同じ)。`linearGradient`・`radialGradient` の塗りは、表せる範囲で §3 のグラデーションにする (線形はどのアフィン変換でも厳密。円にならない放射は近似の円)
- group の名前は `<title>`、なければ既定の「グループ」。図形は種類の既定の名前。結果のルートの group は、埋め込み SVG のノードの名前・表示・ロック・不透明度を引き継ぐ
- `path` の `d` は、`A` (円弧) を含むすべての命令を受け、点の形にする (円弧は 3 次ベジェで近似)
- 変換 (`transform` と親から掛かるもの): パスと線は点に掛ける (厳密)。矩形・楕円は、平行移動・回転・縦横の拡大だけで表せれば箱と `rotation` に、表せなければ (傾斜、回転と縦横の違う拡大の組み合わせ) パスにする。テキストは近似し、一覧に「位置が近似」を必ず出す (テキストを含む SVG では、いつも確認のダイアログが出る)。左右反転したテキストは、反転を除いた向き (変換した y 軸の向き) で正立した文字にする
- 見た目の属性: 表示属性と `style` 属性 (ポリシーが許すもの)、継承 (`fill` `stroke` `stroke-width` `fill-opacity` `stroke-opacity` `fill-rule` `stroke-linecap` `stroke-linejoin` `stroke-dasharray` とフォント)、`currentColor` (`color` が無ければ黒)。`opacity` はノードの不透明度 (ルートの `svg` の `opacity` は埋め込み SVG のノードの不透明度と掛けてルートの group に)、`fill-opacity` と `stroke-opacity` は塗りと線の不透明度。線の太さと破線の長さには、変換の拡大率 (行列式の平方根) を掛ける。CSS と同じく、読めない値と長すぎる値 (`style` の値 4096 文字、数値・長さ・色・不透明度 256 文字を超えるもの) は無視して継承した値を使う。`url()` の後の代わりの塗りは `none` か色だけ
- 塗りも線もない形 (`stroke` のない `<line>` など) は作らない
- 近似して一覧に出すもの: 線のグラデーション (中ほどの停止点の単色)、`pattern` の塗り (代わりの色)、線だけのテキスト (線の色で塗る)、円にならない放射グラデーション、表せないグラデーションの変形、放射の焦点、17 個以上の停止点、縦横で違う拡大を受けた線の太さ、1 行の途中で変わるテキストの書式、上限を超える値
- 落として一覧に出すもの: `clipPath`、`mask`、`filter` とその中身、`image`、`marker`、`textPath`、`stroke-dashoffset`、`stroke-miterlimit` が 4 でないもの、`vector-effect`、`paint-order`、グラデーションの `spreadMethod`、入れ子の `svg` の切り抜き、循環しているか深すぎる `use`、SVG の枠の外にはみ出した部分 (今の描画では `<image>` に切り抜かれて見えないもの。形と線の太さの半分、テキストは字の大きさから見積もる)。`display: none` と `visibility: hidden` の要素は黙って飛ばす。テキストの `rotate` `textLength` `writing-mode` `dominant-baseline`、線の角の `arcs` / `miter-clip` (マイターにする) は読まない
- 落とす・近似するものがあれば、確認のダイアログ (`ConvertConfirmDialog`) に種類と件数を出し、「変換する」を選んだときだけ行う。なければそのまま行う。ダイアログは「変換する」にフォーカスを置き、閉じたら元のフォーカスへ戻す。Enter と Esc はダイアログが受けてキャンバスへ渡さない。Esc で取り消しても選択は変えない
- 結果は、埋め込み SVG のノードの位置に、同じ名前の group として置く (埋め込み SVG の回転と親の frame の向きは §4.11.2 のとおり子へ写す)。変換の後もスコープには入らない。履歴 1 件。参照されなくなったアセットは保存の前に落ちる (§3.4)
- 変換できる形が 1 つもないとき (空の group は検証に落ちる)、結果がノード数・点の数の上限を超えるときは変換せず、理由を出す
- 重い SVG で画面を止めないよう、仕事の量に上限を置く (`MAX_WORK` = 300,000。要素 1 つで 1、テキストの中の要素 8、属性やテキストの 256 文字ごとに 1、作るパスの点 16 個ごとに 1)。`use` の深さ 32、要素の入れ子 256。超えたら `tooLarge` で断る。作るパスの点が文書の上限を超えると分かった時点でも断る
- v1 から引き継いだ作品の埋め込み SVG (`legacy`) にも使える (ADR-0028)

## 5. 画面

### 5.1 配置

```
┌ 作品バー: [作品 ▼] [新規] [取込] タイトル タグ [削除] ……… 未保存 [保存 ⌘S] ┐
├──────────┬──────────────────────────────────┬──────────────┤
│ レイヤー │ ルーラー                          │ プロパティ   │
│          │ キャンバス                        │              │
│          │        ( ツールバー: 下中央 )     │              │
└──────────┴──────────────────────────────────┴──────────────┘
```

- 作品バーは SVG-Edit の時の `VectorWorkspacePage` のものを引き継ぐ (作品の切替、新規、取込、タイトル、タグ、未保存の表示、保存、削除)。ボタンは「アイコン＋短い名称」(`ui-design.md` v1.15)
- 開けない作品 (読めない payload (v3 の検証を通らないもの、v2 の検証を通らず変換できない v2) と、変換できない v1) では、エディタを出さずに理由を出し、保存と取込を止める。新規・削除・再試行・作品の切替はできる。変換できない v1 には「元の SVG を書き出す」を出し、削除の確認にも先に書き出せることを添える (ADR-0027)
- 作品バーの「取込」は、今の作品に画像や SVG を置く (ツールバーの「画像」と同じ)。書き出しはプロパティパネルの「書き出し」の節で行い、作品バーには書き出しのボタンを置かない (対象・形式・倍率を節が持つので、作品バーのボタンと結果が分かれないように)
- レイヤーパネルは幅 220 px、プロパティパネルは幅 240 px。レイヤーパネルは Alt/Option+1 で開閉する
- ツールバーはキャンバスの下中央に浮かせる。並びは 選択、フレーム、矩形、楕円、多角形、星、線、ペン、鉛筆、テキスト、画像、手のひら、倍率 (`toolbar/toolbarItems.ts`)。メニューにまとめず、どれも 1 回で選べるように並べる。点の編集のツール (`pathEdit`) は出さない (パスを選んで Enter かダブルクリックで入る)
- 色とトークンは `ui-design.md` §2 に従う。キャンバスの地は `--bg-muted` にする (ダークでは `--bg` より暗い面がないため、ライトとダークで同じトークンを使う)

### 5.2 レイヤーパネル

- 前面のノードを上に並べる。frame、group、ブーリアンは開閉できる
- 行: 種別のアイコン、名前、表示の切替、ロックの切替。ダブルクリックで名前を変える。パスと、ブーリアンの演算ごと (合体・型抜き・交差・中マド) のアイコンがある。結果を求められなかったブーリアンの行には注意のアイコンを出す (§4.15.3)
- ブーリアンの子は並べ替えられる。子にできない種類のノードは、ブーリアンの中にも子の間にも落とせない (§4.15.1)
- 並べ替えと親の付け替えは `@dnd-kit` のポインター操作で行う。兄弟の最背面 (開いている frame / group のさらに背面) を含め、どの位置へも動かせること。ドラッグの途中で一覧がスクロールしても、落とす位置の判定がずれないこと
- 行の数が数千になっても、ノード 1 個の追加・削除・開閉や選択の変更で全行を描き直さない
- 行のクリックは選択 (Shift / Cmd で複数)。キャンバスの選択と同期する

### 5.3 プロパティパネル

選択に応じて節を出す。複数選択で値が違う欄は「混在」と表示する。

入力欄の確定の規則:

- 確定は、入力を始めた時点で選んでいたノードに当てる。入力の途中で選択が変わっても、新しい選択には当てない。対象のノードがなくなっていたら捨てる
- 何も打っていなければ、フォーカスが外れても確定しない (前のノードの値を別のノードに書き込まない)。入力の途中で Undo などにより値が変わった場合も、打っていなければ何もしない
- 確定 1 回が履歴 1 件。値が変わらない確定は履歴も `revision` も増やさない
- 色の選択 (`<input type="color">`) は、続けて動かしている間をまとめて履歴 1 件にする。`change` が閉じたときにだけ来るとは限らない (WebKit は色を選ぶたびに出す) ので、最後の入力から一定時間 (0.5 秒ほど) 何もなければ確定する形にする
- 整列と等間隔を含め、結果の座標や大きさが §3.5 の範囲を超える操作は当てない

| 節 | 対象 | 欄 |
|---|---|---|
| ツールの設定 | 多角形・星のツールを選んでいる間 | 頂点の数、凹み (星、%) (§4.14) |
| 整列 | 2 個以上、または frame の中の 1 個 | 左・中央・右・上・中央・下、横と縦の等間隔 |
| 位置と大きさ | すべて | X、Y、W、H (線は始点と終点)。箱を持つノードは回転 (度) と左右反転・上下反転のボタン。回転したノードの X / Y / W / H の意味は §4.11.5 |
| 点 | 点の編集中 | 選んだ点の X / Y (親の座標系) と連動の種類 (§4.13.3) |
| 見た目 | すべて | 不透明度、角丸 (frame・矩形・画像) |
| 塗り | frame、矩形、楕円、テキスト、パス、ブーリアン | なし / 単色 / 線形 / 円形、色、不透明度、停止点、向き |
| 線 | frame、矩形、楕円、線、パス、ブーリアン | 色、不透明度、太さ、端、角、破線 |
| 影 | frame、矩形、楕円、テキスト、画像、パス、ブーリアン | X、Y、ぼかし、色、不透明度 |
| 文字 | テキスト | フォント、サイズ、太さ、斜体、行の高さ、字間、揃え、大きさの決め方 |
| フレーム | frame | プリセット、はみ出しを切り抜く |
| パス | パス | 塗りの規則 (`nonzero` / `evenodd`) |
| ブーリアン | ブーリアン | 演算の切替 (§4.15.4) |
| 変換 | 対象があるとき | パスに変換、ブーリアン演算の 4 つ (2 個以上の選択)、線のアウトライン化、編集できる形に変換 (埋め込み SVG 1 個) |
| 書き出し | すべて (選択なしはページ) | 形式、倍率、書き出し |

何も選んでいないときは、ページの設定 (ルーラー、グリッド、グリッドの間隔、グリッドへのスナップ) を出す。

線の端・角・破線:

- 線の節に、端 (なし・丸・四角)、角 (マイター・丸・ベベル)、破線を足した。破線は、数値をスペースかカンマ (全角を含む) で区切って入れる 1 つの欄 (例 `4 2`、`panels/fields/DashField.tsx`)。空は実線。複数選択で値が違うときは空の「混在」で、空のまま確定すると全部を実線にする
- 対象は線を持てるすべてのノード (frame、矩形、楕円、線、パス、ブーリアン)

「変換」の節:

- 操作は登録口 `panels/sections/convertActions.ts` の `CONVERT_ACTIONS` に並べる (パスに変換、ブーリアン 4 つ、線のアウトライン化 `outline/convertAction.ts`、編集できる形に変換 `svgconvert/convertAction.ts`)。操作を書く側は `convertSupport.ts` だけを読む (`ConvertAction` の `availability(ctx)` と `run(store)`、変更を当てる `applyConvertChange`、断る理由を出す `refuseConvert`)。ショートカットも同じ操作を呼ぶ
- `availability` は描き直しのたびに呼ばれるので軽くする (選択の形は文書と選択ごとに 1 回だけ求めて使い回す。ノード 2 万個で 2 ms ほど)。出す操作がないときは節を出さない。点の編集中は何も出さない
- 断る理由は、今は取込の通知 (`assets/status.ts` の `showImportNotice`) で出している。エディタ全体の通知にするのは残り (§7.7)

| `Cmd/Ctrl` + `+` / `-` | ズームイン / ズームアウト |

| `Cmd/Ctrl+]` / `Cmd/Ctrl+[` | 1 つ前面へ / 1 つ背面へ |

### 6.1 どのセッションにも共通の規則

- `main` から切った worktree で作業し、§4.1 の自分の担当だけを触る
- 新しい実行時の依存 (npm、crate) を足さない。必要だと考えたら足さずに報告する
- 新しいコードを画面 (`src/modules/registry.ts`、`VectorWorkspacePage.tsx`) とストレージ (`current_payload_version`) につながない
- 切替までは、Rust の新しいコードがテストからしか呼ばれない。未使用の警告は、切替 PR で外すことをコメントに書いた `allow` で抑える
- テストは純関数を中心に書く。DOM を使うものは既存の vitest (jsdom) で書く
- macOS 12 の WKWebView (Safari 15 相当) で動く構文と API だけを使う (`requirements.md` §3.2)。正規表現の後読み (`(?<=…)` `(?<!…)`) は Safari 16.4 からなので使わない。読み込み時に例外になり、キャンバスが開かなくなる
- PR の前に `npm run typecheck`、`npm run lint`、`npx vitest run --dir src`、Rust を触ったら `cargo fmt --check`、`cargo clippy`、`cargo test` を通す
- 報告には、作ったもの、確かめた方法、確かめられなかったこと、契約に対する要望を書く
- PR は下書き (draft) で作る。オーケストレーターが検証してから下書きを外す (検証の前の版が自動マージで `main` に入らないようにする)

### 6.2 開発用の画面

エディタの部品だけを、アプリの IPC なしで開く画面。「描画とビューポート」のセッションが作り、切替の後も第 2 段階以降の実装と検証に使う。

- リポジトリ直下の `canvas-harness.html` と `src/modules/vector/editor/dev/` (入口と `EditorHarness.tsx`)
- `npm run dev` のあと `http://localhost:1420/canvas-harness.html` で開く。Tauri の IPC は使わず、契約データの `full` を読み込んだエディタを表示する
- `vite build` の入力には入れない (配布物に含めない)。切替の後も残す (第 2 段階以降の実装と検証に使う)
- 文書は、`fitTextNodes` でテキストの大きさを求め直してから `load` に渡す (切替後の画面と同じ手順)
- 文書は `?doc=` で選ぶ (`full`、`stage2`、`empty`、`sample`、`stress`)。`stage2` は第 2 段階のノード (回転、線の端・角・破線、パス、4 つのブーリアンと入れ子) を含む。コンソールの `__canvasHarness` / `__canvasImport` から読み込みと取込を試せる

### 6.3 統合ブランチで進める

第 2 段階 (ADR-0028) の進め方。版を上げる段階や、第 1 段階のコードを広く書き換える段階でも同じ形を使える。

- 作業は `main` から切った統合ブランチ (第 2 段階は `canvas-stage2`) に集め、すべてそろったら統合ブランチから `main` への PR 1 本で切り替える (§7.5)。`main` はそれまで前の段階のままで、いつでもリリースできる
- 各セッションは統合ブランチから切った worktree で作業し (§6.1 の「`main` から切った worktree」に代わる)、統合ブランチ宛ての PR を下書きで出す (`gh pr create --base <統合ブランチ> --draft`)。オーケストレーターが検証し、squash でマージする
- `main` の修正は、オーケストレーターがときどき統合ブランチへマージする
- CI は統合ブランチ宛ての PR と、統合ブランチへの push でも動かす (`ci.yml` の `pull_request` と `push` の `branches` に足し、切替の PR で外す)
- 統合ブランチでは新しい版を有効にしてよい。開発用の画面と `npm run tauri:dev` で、つないだまま確かめる。§6.1 のうち「画面とストレージにつながない」「未使用の `allow`」は当てはまらない (版を上げるまで使われない Rust のコードを除く)。そのほかは同じ
- 先に設計と契約 (型、上限、契約データ) の PR を入れ、版の定数を上げるだけで新しい版に切り替わる形を Rust 側に用意してから (第 2 段階は A)、画面側の版を上げる (C1)

普段のデータを守る:

- 統合ブランチでは `src-tauri/tauri.conf.json` の `identifier` を別の値 (第 2 段階は `com.zredjet.mymtools.stage2`) にする。`tauri:dev` と CI のビルドはデータを `~/Library/Application Support/<identifier>/` (Windows は `%APPDATA%\<identifier>\`) に置き、普段使いのデータを新しい版に書き換えない。切替の PR で戻す
- CI は、`main` 宛ての PR と `main` への push で `identifier` が `com.zredjet.mymtools` であることを確かめる (`ci.yml` の lint のジョブ。戻し忘れたまま `main` に入ると、利用者のアプリが別のデータフォルダを開き、作品が消えたように見えるため。統合ブランチがない間も残す)
- 確かめるのに作品が要るときは、普段のアプリの JSON エクスポートを、統合ブランチのアプリに取り込んで使う。バックアップのリストアは、自分のバックアップのフォルダのファイルしか受けないので、使うなら統合ブランチのデータフォルダの `backups/` へ複製してから戻す
- 統合ブランチのデータフォルダは、どのセッションのブランチでも共有される。あるブランチの途中の形で書いた行が、別のブランチでは開けないことがある。PR を検証するときは、データフォルダを空にするか、JSON から入れ直す
- `tauri.conf.json` の `identifier` の行は `version` の行の隣にあるので、リリースの後に `main` を取り込むと衝突する。取り込む人が解く
- 切替の前に書いた新しい版の行は、捨てる前提にする。形が途中で変わっても版は上げず、途中の形で書いた行を変換する道は作らない

### 7.1 つないだもの

- `VectorWorkspacePage.tsx` を `EditorRoot` と `editorStore` につないだ (読み込み、保存、未保存の確認、作品の切替、新規、取込、書き出し、削除)。表示名は「キャンバス」
- 読み込み: payload を `parsePayload` で文書にし、`fitTextNodes(doc, null, canvasTextMeasurer)` でテキストの大きさを求め直してから `load` に渡す。表示位置を既定に戻してから全体を表示する (`load` は表示位置を残すため。キャンバスがまだなければ、開いたときに `CanvasView` が全体を表示する)。読めない payload と、v1 から変換できなかった作品は、理由を出してエディタを出さない (作品の切替、新規、削除、再試行はできる)
- 編集の途中のものを入れる (`flushEdits`)。保存 (`"save"`) と、離れる前の確認 (`"leave"`) で分ける。どちらも、ポインターのドラッグを取り消し (途中で確定しない。§4.4)、進行中のジェスチャーを確定する
  - 保存は編集を終えない (続けて押した Backspace などが選択中の図形に効かないように): 本文の編集はジェスチャーの確定だけ (§4.7)。レイヤー名の欄は閉じずに名前を確定する (`panels/fields/commitInPlace.ts`)。数値・色・フォント名などの欄は blur して値を入れ、フォーカスと、カーソル・選択の範囲を戻す
  - 離れる前は編集を終える: 入力欄は blur して値を入れ (欄が残っていればフォーカスと範囲を戻す)、本文の編集は `commitTextEdit()` で終える
- 保存: `flushEdits` → `checkSavable` → `toPayload` → `core_create_item` / `core_update_item`。未保存かどうかは、保存した時点の `revision` とタイトル・タグで判定する。ドラッグの途中は保存と新規のキーを受けない。日本語入力の変換中 (`isComposing`、`keyCode === 229`) は ⌘S を受けない (既定の動作も止めない)。作ったばかりで空のテキストは保存する文書に入れず、「未保存」の表示にも数えない (§4.7)
- 作品の切替、新規、削除、画面を離れる、ウィンドウを閉じる、同じ URL への開き直しの前に、`flushEdits` をしてから未保存を確かめる。閉じるのを認めても、閉じるのに失敗したら以後の確認は効く (閉じ直しの間は `windowClose.ts` がガードを飛ばす)。取込の途中は作品を切り替えない。確認のモーダル (`aria-modal="true"`) が開いている間、キャンバスはキーを取らない (§4.4)
- 取込: `setImportFileReader` に、ファイル選択 (`plugin-dialog`、PNG / JPEG / WebP / SVG) と `vector_read_image` / `vector_read_file` の結果を渡す関数を登録した。作品バーの「取込」は `importFromPicker`。OS からのドロップは Tauri の webview のイベントで受け、画面がファイルを読んでから `importFile(store, file, { at })` に渡す (読む間は作品を切り替えない。複数のファイルは先頭の 1 つだけ。確認のモーダルの間は受け付けない)。イベントの位置の単位は OS で違う (wry 0.55 で確認。macOS は point のまま、Windows は物理 px) ので、Windows だけ `devicePixelRatio` で割ってマウスの `clientX` と同じ値にする (`canvasIo.ts` の `dropPointOnCanvas`)
- 書き出し: §4.9。複数のファイルの途中で書き込みに失敗したら、書いた数 (`ExportWriteResult.written`) と理由 (`error`) を返し、書き出しの節が「n ファイルは書き出しました」を添えて失敗を出す
- 画面を開くたびに `resetLastFrameSize()` を呼び、表示の設定を `DEFAULT_VIEW_OPTIONS` に戻す。画面を離れたら、store から作品と履歴を外す
- Rust: `current_payload_version` を 2 に、`upgrade_payload(1)` を `upgrade::upgrade_v1`、`validate_payload` を `scene::validate` につないだ。`vector_write_file` の SVG の検証を §4.9 に変えた。`protocol.rs` と `vector_editor_url` を消した
- エクスポート: アップグレードに失敗した item は、古い payload と版のまま書き出す (`data-model.md` §7.6)。変換できない v1 の作品があっても、エクスポート全体は止まらず、その作品を `ExportSummary.not_upgraded` で返して完了の表示に出す (ADR-0027)
- 変換できない作品と旧版へ戻すときの守り (ADR-0027): 起動時の最初の変換の前のバックアップ (`pre-payload-vector-v2`)、`update_item` での上書きの拒否、書き戻しに失敗しても変換した結果を返すこと、開けない作品の「元の SVG を書き出す」(`vector_export_original_svg`)。v1 の `text` は変換で求め直す (§3.7)
- SVG ポリシー (`policy.json`、`svg-policy.js`、`svg-policy.d.ts`、`validation-fixtures.json`) を `src/modules/vector/policy/` へ移した。npm の `svgedit`、`prepare:vector`、`test:vector:*`、`scripts/svgedit/` の adapter 群、`bridge.ts`、`third_party/svgedit-NOTICES.txt`、About と `THIRD_PARTY_NOTICES.md` の表記を消した

- マージの前に、利用者が実アプリで確かめる (§7.6)。マージはオーケストレーターが行い、リリースは別に行う

### 7.6 実アプリで確かめること (第 2 段階)

開発用の画面と自動テストでは確かめられないもの。手順と結果は `vector-editor-verification.md` に記録する。

- 普段のデータ: v2 の作品が見た目を変えずに開けること、`pre-payload-vector-v3` のバックアップが 1 回だけ取られること (2 回目の起動では取らない)
- 回転したノードの選択・リサイズ・テキストの編集 (日本語入力の変換の候補の位置を含む)、回転のカーソルの見た目
- トラックパッドでのペン・点の編集・鉛筆 (鉛筆の許容 2 画面 px の感触、長いなぞりの重さ)
- Option+Shift+U / S / I / E と Shift+Cmd+O の実際のキー (macOS の Option で文字が変わるキー)
- ブーリアンの子をドラッグしたときの重さ (WKWebView での演算の速さ)
- 線のアウトライン化の前後の見た目 (閉じた輪郭の破線の始点を含む。WebKit に合わせた)
- v1 の作品の埋め込み SVG の変換 (確認のダイアログ、閉じた後のフォーカス、テキストの位置)
- 埋め込み SVG・回転・パス・ブーリアンを含む文書の PNG と SVG の書き出し
- Windows (WebView2) での同じ項目 (閉じた輪郭の破線の始点の角は、描画が Chromium の規則なのでアウトライン化の結果と違って見える)

### 7.7 残っていること (第 2 段階)

- README の画面イメージ (`vector.png`) の撮り直し (§7.3。第 2 段階の画面で撮る)
- 「変換」の節が断る理由を、取込の通知 (`assets/status.ts`) ではなくエディタ全体の通知で出す
- `canvas/shortcuts.ts` が `panels/` (変換の操作) を読んでいる (キャンバスがパネルに依存する)。動作の関数を `state/` に移すとよい
- 多角形と星のツールは、矩形ツールが `apply` / `updateGesture` で入れることに頼って差し替えている (§4.14)。作成ツールにノードを作る関数を渡せる口を足して置き換える
- 線のアウトライン化の既知の近似: 塗りと線のあるノードの影 (§4.16)、ちょうどの尖点は平ら、太い線を持つ小さく曲がった形で許容以下の細い穴が残ることがある
- `model/types.ts` の `ContainerNode` は使われていない (契約のファイルなので残してある)
- 開発用の検証で、SVG ポリシーの `validateSvg` が jsdom では要素の数の 2 乗の時間になる (ブラウザでは比例。テストの時間だけの問題)

### 7.8 受入 (第 2 段階)

ADR-0028 の Acceptance に従う: v1 と v2 の作品が新しい版で開け、見た目が変わらない。v1・v2 の `vector` を含む古いエクスポートファイルを取り込める。回転、パス、ブーリアン、線の端・角・破線を含む作品が保存・再読み込み・JSON の入出力・バックアップで往復する。Rust と TypeScript の v3 の検証が、共有の契約データ (`payload-v3.json`) で同じ合否になる。portable ZIP は各 80,000,000 bytes 以下。自動テストでの確認、開発用の画面での確認、実アプリでの確認を分けて `vector-editor-verification.md` に記録する。
