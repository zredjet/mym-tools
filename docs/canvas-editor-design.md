# キャンバス (自作エディタ) の設計

最終更新: 2026-11-14 / ステータス: Draft v0.5

ADR-0026 の決定を実装するための設計。保存形式、エディタ内部の境界、画面、実装の分担を定める。

## 1. 位置づけ

- 対象はモジュール `vector`。表示名は「キャンバス」に変える (ID は変えない)
- SVG-Edit 同梱 (ADR-0021) を、自作の Figma 風エディタに置き換える
- **切替 PR がマージされるまで、`main` で動くのは SVG-Edit**。それまで `requirements.md` / `ui-design.md` / `data-model.md` / `module-contract.md` のベクター描画の記述は ADR-0021 のままにし、切替 PR で本書の内容へ書き換える (§7)
- 切替までの新しいコードは `src/modules/vector/editor/` と `src-tauri/src/modules/vector/` の新規ファイルに置き、画面にもストレージにもつながない

## 2. 範囲

### 2.1 用途

UI モックアップ・画面設計、アイコン・ロゴ、バナー・サムネイル。図解は `diagram` (draw.io) の役割で、ここでは扱わない。

### 2.2 段階

| 段階 | 内容 |
|---|---|
| 1 | モックアップとバナー。この段階で SVG-Edit から切り替える (§2.3) |
| 2 | アイコン・ロゴ。ペンツール、パス編集、ブーリアン演算、編集できる形での SVG 取込 |
| 3 | コンポーネントとインスタンス、色・文字のスタイル、ページ切替の画面 |
| 4 | オートレイアウト、制約 |

### 2.3 第 1 段階の機能

- 無限キャンバス、ズーム、パン、ルーラー、ガイド線、グリッド
- ノード: フレーム、グループ、矩形、楕円、線、テキスト、画像、埋め込み SVG (編集不可)
- 表現: 単色とグラデーション (線形・円形) の塗り、単色の線、角丸、不透明度、ドロップシャドウ
- 操作: 選択、範囲選択、移動、リサイズ、複製、削除、グループ化、重なり順、整列、等間隔、フレーム間の移動
- 補助: 整数ピクセルへの丸め、スマートガイド (辺と中心)、ガイド線とグリッドへのスナップ、フレームのプリセット
- パネル: レイヤー (名前変更、表示、ロック、並べ替え)、プロパティ
- Undo / Redo、エディタ内のコピー・切り取り・貼り付け
- 取込: PNG / JPEG / WebP、SVG ファイル (埋め込み SVG として置く)
- 書き出し: SVG、PNG (1 倍・2 倍・3 倍)。対象はフレーム、選択範囲、ページ全体
- 保存は明示操作 (保存ボタンと Cmd/Ctrl+S)。作品は一覧を挟まず直近のものを開く

### 2.4 第 1 段階に入れないもの

回転、画像のフィットと切り抜き、文中の一部だけの書式、複数の塗り、線の内側・外側揃えと破線、矢印、OS のクリップボードとの画像のやり取り、等間隔のスマートガイド、ページ切替の画面、表示設定の永続化。

### 2.5 対象外

Figma ファイルの読み書き、共同編集、プロトタイピング、プラグイン、任意の外部 SVG の完全な取込、PDF、Illustrator 形式、テキストのアウトライン化。

## 3. 保存形式 (payload v2)

型は `src/modules/vector/editor/model/types.ts`、上限は `model/limits.json`、検証の合否と変換結果の例は `model/fixtures/payload-v2.json` にある。Rust と TypeScript は同じ 2 つの JSON を読む。

### 3.1 全体

```jsonc
{
  "pages":  [ { "id": "...", "name": "...", "children": ["..."], "guides": [] } ],
  "nodes":  { "<id>": { "id": "<id>", "type": "rect", ... } },
  "assets": { "<id>": { "kind": "image", ... } },
  "text":   "検索用テキスト"
}
```

- `nodes` は ID から引く平たい表。木の形は `pages[].children` と frame / group の `children` が決める
- 重なり順は `children` の配列の順で、先頭が最背面
- すべてのフィールドは必須。未知のフィールドは拒否する。形式を変えるときは payload のバージョンを上げる (ADR-0006)
- エディタのメモリ上のモデルも同じ形を使い、変換層を持たない

### 3.2 座標

- 単位は px。小数を持てるが、エディタの操作は位置と大きさを整数に丸める
- ページ直下のノードはページ座標。frame の子は frame の左上を原点とする
- group は座標系を作らない。group の子は group の親の座標系で持ち、group の外接矩形は子から求める
- 回転は持たない

### 3.3 木の規則

- どのノードも、ちょうど 1 つの親 (ページ、frame、group) の `children` に 1 回だけ現れる
- `children` が指す ID は `nodes` に存在する。`nodes` のキーとノードの `id` は一致する
- group の `children` は 1 個以上。frame は 0 個でもよい
- 深さは `maxDepth` 以下 (ページ直下を 1 とする)
- ノード、ページ、アセットの ID は別々の名前空間で、書式はどれも `idPattern`
- `__proto__` は ID に使えない (JavaScript でオブジェクトを表として使うと、この名前だけ正しく扱えないため)

### 3.4 アセット

- `image`: PNG / JPEG / WebP の base64。標準の字母 (`+` `/`) で、パディングは必須、空は不可
- `image` の `mime` と中身の先頭バイトが一致すること (既存の `validate_image` と同じ判定)。PNG は 24 バイト以上でシグネチャが合う、JPEG は 4 バイト以上で `FF D8 FF` から始まる、WebP は 12 バイト以上で `RIFF` から始まり 8〜11 バイト目が `WEBP`
- PNG は IHDR の幅と高さが 1 以上 `maxImageSide` 以下、積が `maxImagePixels` 以下
- `svg`: 既存の SVG ポリシー (`scripts/svgedit/policy.json`、`validate_svg`) を通った SVG と、そこから抽出した `text` (v1 と同じ抽出結果と完全に一致すること)
- アセットの `width` / `height` は image も svg も、0 より大きく `maxSize` 以下。画像の実際の大きさと一致するかは確かめない
- アセットはノードから参照されているものだけを持つ。エディタは保存の前に参照されていないアセットを落とす
- 同じ画像を 2 回置いたら、アセットは 1 つを共有する (挿入時に中身を比べる)
- 全アセットの合計 (image の `data` の文字数 + svg の UTF-8 の長さ) は `payloadBytes` 以下
- base64 の判定は 20 MiB の文字列でも正しく動くこと。繰り返しを入れ子にした正規表現を全体に当てると、JavaScript のエンジンによっては数 MiB で誤判定や例外になる

### 3.5 ノードの規則

`types.ts` の型に加えて次を確かめる。数値は有限の JSON number に限る。

| 対象 | 規則 |
|---|---|
| ノードとページの `name` | `maxNameLength` 文字以下。空でもよい |
| `opacity` (ノード、塗り、線、影、停止点) | 0 以上 1 以下 |
| `x` `y` `x1` `y1` `x2` `y2`、ガイド線の `position` | 絶対値が `maxCoordinate` 以下 |
| `width` `height` | 0 以上 `maxSize` 以下 |
| `radius` | 0 以上 `maxRadius` 以下 |
| 色 | `colorPattern` |
| 線の `width` | 0 より大きく `maxStrokeWidth` 以下。線なしは `stroke: null` |
| 影 | `x` `y` は絶対値が `maxShadowOffset` 以下、`blur` は 0 以上 `maxShadowBlur` 以下 |
| グラデーション | 停止点は `minGradientStops`〜`maxGradientStops` 個、`offset` は 0〜1 で昇順 (同値可)。`from` `to` `center` の各成分は絶対値 100 以下、`radius` は 0 より大きく 100 以下 |
| テキスト | `text` は `maxTextLength` 文字以下。`fontFamily` は 1〜`maxFontFamilyLength` 文字で制御文字 (U+0000〜U+001F、U+007F〜U+009F) を含まない。`fontSize` は `minFontSize`〜`maxFontSize`。`fontWeight` は 100〜900 の 100 刻み。`lineHeight` は null か、0 より大きく `maxLineHeight` 以下。`letterSpacing` は絶対値が `maxLetterSpacing` 以下 |
| image / svg ノード | `assetId` が同じ種類のアセットを指す |
| ページ | 1〜`maxPages` 個、ID は重複しない。ガイド線は `maxGuidesPerPage` 本以下 |
| 全体 | ノードは `maxNodes` 個以下。全テキストノードの `text` の合計は UTF-8 で `maxTotalTextBytes` 以下 |
| 文字列 | 対になっていないサロゲートを含まない。Rust の JSON の読み込みが受け付けないので、TypeScript 側の検証で拒否する |

文字数は Unicode のコードポイント数で数える。

### 3.6 検索用テキスト

文書から次の規則で求め、`text` に入れる。Rust は保存と JSON 取込のたびに求め直し、一致しなければ拒否する (v1 と同じ考え方)。

1. ページを配列の順にたどり、各ページの `children` を配列の順に深さ優先でたどる
2. frame は `name`、text は `text`、svg はアセットの `text` を拾う。group は拾わずに子へ進む。ほかのノードは拾わない。`visible` が false でも拾う
3. 拾った文字列ごとに、空白で区切って空の要素を捨て、半角スペース 1 個でつなぐ。空になったものは捨てる
4. 残ったものを半角スペース 1 個でつなぐ

空白は Unicode の White_Space (Rust の `char::is_whitespace` と同じ集合: U+0009〜U+000D、U+0020、U+0085、U+00A0、U+1680、U+2000〜U+200A、U+2028、U+2029、U+202F、U+205F、U+3000)。JavaScript の `\s` は U+FEFF を含み集合が違うので使わない。

`text` は UTF-8 で `textBytes` 以下。超える文書は保存しない。

### 3.7 v1 から v2 へ

`upgrade_payload(1, { svg, text })` は、v1 の SVG を埋め込み SVG 1 個の文書にする。結果は入力だけで決まる。

- ページは 1 つ (`id: "page1"`、`name: "ページ 1"`、ガイド線なし)
- ノードは 1 つ (`id: "legacy"`、`type: "svg"`、`name: "SVG"`、位置 0,0、表示・ロックなし・不透明度 1)
- アセットは 1 つ (`id: "legacy"`、`svg` と `text` は v1 のまま)
- 大きさは、ルートの `width` / `height` 属性 (数値、`px` 付きも可) が両方とも正ならその値。なければ `viewBox` の幅と高さ。それもなければ 640 × 480。1 以上 `maxSize` 以下に収める
- アセットの `text` は v1 の `text` のまま。文書の `text` は、変換後の文書から §3.6 の規則で求める。v1 の抽出は空白の集合が違う (U+0085 を空白として扱わない) ので、その文字を含む作品では v1 の `text` と違う値になる。それ以外では同じ値になる

変換の結果は v2 の検証を通ること。通らない場合 (今の SVG ポリシーを通らなくなった古い作品など) は変換を失敗として返し、v1 のまま残す。壊れた v2 を書き込まない。

この書き換えは戻せない (ADR-0006 の通常の挙動)。`data_revision` は増やさない。

## 4. エディタの構造

### 4.1 ディレクトリと担当

`src/modules/vector/editor/` の下。契約の PR で型と仮置きのファイルを置いてあり、各セッションは自分の担当のファイルだけを作り、置き換える。

| 場所 | 中身 | 担当 |
|---|---|---|
| `model/types.ts` `model/limits.*` `model/fixtures/` | 保存形式の型、上限、契約データ | 契約 (変更しない) |
| `state/types.ts` `render/types.ts` `tools/types.ts` `tools/registry.ts` `EditorRoot.tsx` | 状態・描画・ツールの契約、配置 | 契約 (変更しない) |
| `model/` のそのほか | 文書の操作、幾何、整列、検索用テキスト、検証 | モデル基盤 |
| `state/` のそのほか | store、履歴、エディタ内クリップボード | モデル基盤 |
| `render/` のそのほか | ノードから `SvgEl` への変換、React と文字列への出力 | 描画とビューポート |
| `canvas/` `toolbar/` `tools/handTool.ts` `dev/` | キャンバス、ルーラー、グリッド、ツールバー、開発用の画面。ショートカットの割当表 `canvas/shortcuts.ts` には、編集のショートカットを「選択と変形」が足す | 描画とビューポート |
| `panels/LayersPanel.tsx` `panels/PropertiesPanel.tsx` `panels/layers/` `panels/fields/` `panels/sections/` (下の 2 つを除く) | パネル。フレームのプリセットの一覧 `panels/sections/framePresets.ts` もここに置く | パネル |
| `tools/selectTool.ts` `tools/select/` `hit/` `snap/` | 選択、変形、ヒットテスト、スナップ、ガイド線 | 選択と変形 |
| `tools/{frame,rect,ellipse,line,image}Tool.ts` `assets/` | 作成ツール、画像と SVG の取込。フレームのプリセットは `panels/sections/framePresets.ts` を使う | 作成ツールと画像 |
| `text/` `tools/textTool.ts` `panels/sections/TextSection.tsx` | 行分割、大きさの求め直し (`text/fit.ts`)、計測 (`render/measureText.ts` の差し替えを含む)、フォント、本文の編集 | テキスト |
| `export/` `panels/sections/ExportSection.tsx` | SVG / PNG の書き出し | 書き出し |

契約のファイルを変えたいときは変えずに報告する。足りないフィールドを足すのは、ほかのセッションの前提を壊さない追加に限る。

`text/layout.ts` の `layoutText` と `text/fit.ts` の `fitTextNodes` は、名前と引数が契約で、中身は仮の実装を「テキスト」が置き換える。ほかのセッションは、この 2 つを呼ぶだけにする。

担当の外のファイルのうち、次だけは、書いてある目的のための最小限の変更をしてよい。同じファイルを 2 つのセッションが触らないように割り当ててある。

| セッション | ファイル | 目的 |
|---|---|---|
| 選択と変形 | `canvas/shortcuts.ts` | 「編集」の節にショートカットを足す |
| 選択と変形 | `canvas/Rulers.tsx` | ルーラーからガイド線を引き出す、戻して消す |
| テキスト | `canvas/DocumentLayer.tsx` | 本文の編集中のテキストを文書の層で描かない |
| テキスト | `panels/sections/propertyOps.ts` | テキストの W / H を確定したあと、同じ変更の中で `fitTextNodes` を通す |
| 書き出し | `dev/main.tsx` | 開発用の画面で書き出しを試せるよう、保存先の関数を登録する |

### 4.2 状態

- `state/store.ts` が Zustand の vanilla store を 1 つ作り、`editorStore` と `useEditorStore(selector)` を公開する。契約は `state/types.ts` の `EditorStore`
- これはエディタの中だけの状態で、アプリ全体の状態 (`useAppStore`) には入れない。React の Context も使わない
- 文書の変更は「文書を受け取り、変更後の文書を返す純関数」(`DocRecipe`) で行い、`apply` か `beginGesture` / `updateGesture` / `commitGesture` を通す。変わらないノードは同じオブジェクトを使い回す
- 履歴は文書と選択の組のスナップショットで、上限 100 件。大きな画像の文字列はアセットのオブジェクトごと共有されるので複製されない
- `revision` は文書が変わるたびに増える。呼び出し側は保存した時点の `revision` と比べて未保存かどうかを判定する
- コンポーネントは必要な部分だけを selector で購読し、ノード 1 個の変更で全体を描き直さない
- ジェスチャーの途中で `apply` か `beginGesture` を呼ぶと、先に今のジェスチャーを確定する。途中の `undo` / `redo` はジェスチャーを取り消すだけ
- `cancelGesture` は文書と選択を開始時点へ戻す
- `revision` は `apply`、`commitGesture` (文書が変わったとき)、`undo`、`redo` で 1 増える。`updateGesture` の途中では増えない
- 中身が変わらない操作は、引数の文書そのものを返す。履歴も `revision` も増やさない
- 選択は表示中のページのノードに絞る。消えたノードは選択、ホバー、スコープ、本文の編集中から外す
- `load` は表示位置と表示の設定を残し、ツールを選択に戻す
- 保存は、進行中のジェスチャーを確定してから行う (途中の文書を保存して取り消すと、保存内容と画面がずれる)
- ジェスチャーを閉じるのは、開いた側。パネルの色の選択や本文の編集のように長く開くジェスチャーを、キャンバスは取り消さない (§4.4)

### 4.3 描画

- ノードはまず `SvgEl` (SVG 要素の素朴な木) にする (`render/types.ts` の `BuildNodeSvg`)。画面はそれを React 要素にし、SVG 書き出しは同じ木を文字列にする。描画の規則を 2 か所に書かない
- グラデーション、影 (`feDropShadow`)、切り抜き (`clipPath`) の定義は、使うノードのすぐ隣の `<defs>` に置き、ID は `idPrefix` + ノード ID から作る
- image は `<image>` に data URL で、`preserveAspectRatio="none"`。svg アセットも `<image>` に `data:image/svg+xml;base64,` で置く (文書から隔離され、スクリプトは動かず、ID も衝突しない)
- data URL の組み立ては重いので、アセットのオブジェクトをキーにして結果を使い回す
- テキストは `text/layout.ts` の `layoutText` が返す行を `<tspan>` に置く。`foreignObject` は使わない
- 選択枠、ハンドル、ガイド、作成中の枠は、文書の SVG とは別の重ね描き用の SVG に、ページ座標で描く。太さは倍率に関係なく一定にする
- 本文の編集用の `<textarea>` は SVG の中に置けないので、重ね描きのさらに上の HTML の層に、画面座標で置く
- frame の影は、塗りがあれば塗りの矩形が、なければ線の矩形が落とす。子の形の影にはしない。影は必ず子の背面に描く (線だけの frame でも、影が子の上に重ならない)
- テキストの影のフィルタ領域は、斜体や行の高さからはみ出す字形が欠けないよう、フォントサイズに応じて広げる
- 大きさが 0 の外接矩形にはグラデーションを写せないので、そのときは先頭の停止点の色で塗る
- 大きな画像の data URL を、描き直しのたびに走査しない (エスケープや文字の検査は、利用者が入力した文字列だけに行う)
- 画面外のページ直下のノードは描かない
- 性能の目安は数千ノード。超えて重くなったら Canvas のレンダラを足す。そのために、モデル・状態・ツール・ヒットテストは DOM に依存させない

### 4.4 ツール

- `canvas/CanvasView.tsx` が DOM のイベントを `CanvasPointerEvent` / `CanvasKeyEvent` に直し、`tools/registry.ts` の現在のツールへ渡す。ポインターは `setPointerCapture` で追う (HTML5 のドラッグ&ドロップは使わない)
- ツールは store だけを通して文書を変える。ドラッグは `beginGesture` で始め、Esc とフォーカス喪失で `cancelGesture` する
- 作成ツールは 1 回作ったら選択ツールへ戻る
- カーソルは、ふだんはツールの `cursor`。リサイズハンドルの上のように場所で変えたいときは、ツールが `ToolContext.setCursor` で上書きし、null を渡して戻す
- ボタンを押していない移動では、`CanvasPointerEvent.clickCount` は 0 になる
- Space を押している間と中ボタンのドラッグは、どのツールでも手のひらになる。Cmd/Ctrl と一緒の Space では入らない。Space を離したことが届かない場合 (macOS は Cmd を押している間ほかのキーの keyup を送らない) に備え、修飾キーを離したときにも解除する
- ドラッグの途中でホイールやピンチが来て表示位置が変わったら、直前の修飾キーの状態を保ったまま、今のポインター位置での移動をツールへ渡す。手のひらのドラッグは、途中の表示位置の変化を打ち消さない
- `onCancel` は、ドラッグの途中の Esc、ツールの切替、ポインターの取消、ウィンドウからのフォーカス喪失、キャンバスが画面から外れるときに呼ぶ。何もしていないときの Esc は `onKeyDown` へ渡すだけにする
- ツールが `onCancel` で取り消すのは、自分のドラッグが開いたジェスチャーだけ。キャンバスも、ポインターのドラッグの途中だったときにだけ、残ったジェスチャーを取り消す。ドラッグしていないときの Esc、ウィンドウからのフォーカス喪失、キャンバスが画面から外れるときには、開いているジェスチャーに触らない
- 押したまま 4 画面 px を超えて動かした押下 (ドラッグ) は、次の押下をダブルクリックに数えない
- ツールが自分のハンドラの中で `setTool` を呼ぶと、その場で自分の `onCancel` が呼ばれる。作成ツールは、先に `commitGesture` と内部状態の片付けを済ませてからツールを切り替える
- OS のファイル選択ダイアログを開くとウィンドウのフォーカスが外れ、現在のツールの `onCancel` が呼ばれる

キーとフォーカスの規則:

- キャンバスのショートカットは、フォーカスがエディタ (`data-canvas-editor` の中) にあるか、どこにもない (body) ときだけ効く。作品バーやサイドバーなどエディタの外にフォーカスがある間と、モーダルが開いている間は、Space や Esc を含めて何も取らない
- 入力欄にフォーカスがある間と、日本語入力の変換中は、文字キーのショートカットを効かせない
- エディタの中のボタンやチェックボックスにフォーカスがある間は、その部品が使うキー (Space、Enter、矢印) を取らない。ほかのショートカットは効く
- キャンバスを押したら、フォーカスをキャンバスへ移す。入力欄にフォーカスがあれば、先にフォーカスを外して入力を確定させてから、ツールへ渡す (選択が変わる前に確定させる)

### 4.5 ヒットテストと選択

ヒットテストは文書の幾何から求める純関数にする (`hit/`)。DOM の `elementFromPoint` には頼らない。

- 前面から順に調べる。`visible` が false か `locked` が true のノードと、その子孫は当たらない
- 塗りのない図形は線の上だけが当たる。線は太さに 4 画面 px の余裕を足す
- ページ直下の frame は、名前のラベルを押したときだけ frame 自身が選ばれる。中の何もない場所を押すと選択を解除し、ドラッグは範囲選択になる
- ページ直下の frame の子は直接選べる。group と入れ子の frame は、まず全体が選ばれ、ダブルクリックで中に入る (`scopeId`)。Esc で 1 段外へ出る
- Cmd/Ctrl を押しながらのクリックは、いちばん深いノードを選ぶ
- Shift を押しながらのクリックは選択に足し、選択済みなら外す
- 範囲選択は、スコープの中で外接矩形が重なるノードを選ぶ。ページ直下の frame は全体が囲まれたときだけ選ぶ
- group のスコープの中では、group の外接矩形の中の何もない場所もスコープの中として扱う (そこから範囲選択ができ、スコープを出ない)
- 祖先と子孫を同時には選ばない。Shift を押しながらのクリックで足すノードの祖先や子孫が選択にあれば、それを外して入れ替える
- 選択中のノードの上を押したら、選び直さずにドラッグできる。動かさずに離したら、押した位置で選び直す。選択の外接矩形の中の何もない場所からのドラッグは、選択を動かす (ページ直下の frame を選んでいる間は、その中の何もない場所からのドラッグが frame の移動になる)
- 押した位置にあるものの優先順は、リサイズハンドル、ガイド線 (3 画面 px)、frame のラベル、ノード。ダブルクリックはハンドルとガイド線を飛ばす
- クリックとドラッグは、押してから 3 画面 px 動いたかで区別する。動かないクリックは履歴も `revision` も増やさない。押してから取り消したら (Esc、フォーカス喪失)、選択は押す前に戻る
- ホバーの枠とリサイズハンドルは、選択ツールのときだけ出す

### 4.6 変形とスナップ

- 移動とリサイズの結果は整数に丸める
- 移動: Shift で水平・垂直に固定、Alt で複製。矢印キーは 1 px、Shift と一緒なら 10 px
- 移動の丸めは、動かした向きだけに行う。動かしていない向きの小数の座標は変えない。元の位置へ戻したら文書を変えない
- Alt での複製は、ドラッグが始まった時点 (3 画面 px を越えた時点) の Alt で決める。ノード数の上限で複製できないときは、何も動かさない
- リサイズ: 8 個のハンドル。Shift で縦横比を固定、Alt で中心から。画像と埋め込み SVG だけの選択は既定で縦横比を固定し、Shift で解除する
- 線を 1 本だけ選んだときのハンドルは、始点と終点の 2 個。Shift で 45° 刻み、Alt で中点を固定する
- 画面上で 32 px より小さい選択は、辺の内側をリサイズハンドルにしない (中を押せば動かせる)
- 複数選択と group のリサイズは、子孫の位置と大きさを比例させる。テキストはフォントサイズを変えずに枠だけ変える。角丸と線の太さは変えない
- frame のリサイズは子を動かさない。複数選択や group の中の frame も同じで、frame の枠だけが比例して変わる。変えないのは子の座標の値 (frame の中での位置) なので、左辺や上辺を動かすと、子は frame の左上と一緒に動く
- 複製と貼り付けは、元の位置から右下へ 10 px ずらす
- テキストは、横に引くと `auto-height`、縦にも引くと `fixed` になる。どちらに引いたかは、リサイズ前後の外接矩形の幅と高さの比で決める (結果の数値の差では決めない)。縦に引いていなければ、テキストの `height` と `y` 方向の大きさは丸めでも変えない
- テキストを含むリサイズは、`resizeNodes` のあと、同じ `DocRecipe` の中で `fitTextNodes` (`text/fit.ts`) を通す。幅を変えた `auto-height` のテキストは、折り返した結果の高さになる
- 線の `stroke` は null にできない。複数選択に「線なし」を当てたときは、線だけを対象から外す
- group の解除では、group の不透明度を子に掛け合わせ、group が非表示なら子を非表示に、ロック中なら子をロックにする
- ドロップした位置が別の frame の上なら、その frame の子にする。見た目の位置は変えない。つかんだ点がノードの上なら、ポインターの下の最も前面の frame (なければページ直下) が今の親と違うときに付け替える。frame のラベルや、選択の中の何もない場所をつかんだときは、押した点の下の frame と違う frame に入ったときだけ付け替える
- スナップの候補は、同じ親の兄弟と親 frame の辺・中心、ガイド線、グリッド (`snapToGrid` のとき)。6 画面 px 以内でいちばん近いものに吸着し、そろった線を重ね描きする。Cmd/Ctrl を押している間は吸着しない
- ガイド線はルーラーから引き出して作り、ルーラーへ戻すと消える

### 4.7 テキスト

- 行分割は `text/layout.ts` の `layoutText` が行う。`\n` で改行し、`auto-height` と `fixed` は幅で折り返す。和文は文字の間で、欧文は単語の間で折り返す。行頭に来てはいけない句読点と閉じ括弧の前では折り返さず、直前の文字ごと次の行へ送る (ブラウザの `line-break: strict` と同じ向き。本文の編集中の入力欄と折り返しをそろえるため)
- 行分割の時間は、本文の長さにほぼ比例すること。上限いっぱい (`maxTextLength`) の、空白のない文字列でも固まらない
- 幅は `TextMeasurer` で測る。テストでは固定幅の代用品を渡す。ブラウザでの計測は、SVG の描画と同じ幅を返すこと (空白の並び、絵文字、`system-ui` を含む)。canvas の `measureText` が描画と違う幅を返す場合は、SVG の要素で測る
- 折り返すかどうかの判定に使う幅は、そのエンジンの HTML (本文の編集中の入力欄) が組む幅に合わせる。行の幅、揃えの位置、`auto-width` の大きさは描画の幅で求める。WebKit は HTML を折り返せる単位ごとに組み、単位をまたぐカーニングを入れないので、この 2 つが違う (かなの多い行で最大 1% ほど)。エンジンの違いは、名前ではなく実測で決める
- 本文の編集は、テキストの位置に `<textarea>` を重ねて行う (`text/TextEditOverlay.tsx`)。日本語入力の変換中の Enter と Esc は変換の操作として扱い、編集を終えない
- 編集の開始はダブルクリックか Enter、終了は Esc か外側のクリック。空のまま終えたらノードを消す
- テキストツールは、クリックで `auto-width`、ドラッグで幅を決めた `auto-height` を作る
- フォントは同梱しない。候補 (§5.7) のうち、その PC にあるものを一覧に出し、ほかは名前を直接入力する。あるかどうかは、そのフォントを先頭に置いたときと総称フォントだけのときの幅を比べて判定する (`document.fonts.check` はシステムフォントの有無を返さないので使わない)
- 文書のフォントがその PC になければ、プロパティに注意を出し、総称フォントで描く
- `auto-width` / `auto-height` の大きさは開いたときに求め直す。呼び出し側が `load` に渡す前に求め直すので、履歴にも `revision` にも数えない
- 大きさの求め直しは `text/fit.ts` の `fitTextNodes(doc, ids, measurer)` だけで行う。`auto-width` は幅と高さを、`auto-height` は高さだけを行分割の結果に合わせ、`fixed` は変えない。大きさは切り上げた整数にする。`auto-width` の幅が変わるときは、揃えが左なら左端、中央なら中心、右なら右端を保つ。中央揃えの `x` は丸めない (0.5 刻みになりうる。丸めると、変更を重ねるたびに片側へずれていく)
- 本文、フォント、サイズ、太さ、斜体、行の高さ、字間、大きさの決め方、幅を変える操作は、同じ `DocRecipe` の中で `fitTextNodes` を通す (操作 1 回が履歴 1 件)。変わるものがなければ文書をそのまま返すので、余分に呼んでも履歴は増えない
- 本文の編集の開始と終了は store の `startTextEdit` / `endTextEdit` で行う。選択ツールは、テキストのダブルクリックと Enter で `startTextEdit` を呼ぶ。テキストツールは、作った直後に呼ぶ。終了は `TextEditOverlay` が行う (Esc、入力欄からフォーカスが外れたとき)。ウィンドウからフォーカスが外れただけでは終えない
- 保存と、画面を離れる前の未保存の確認は、本文の編集を終えてから行う。そのために、編集をその場で (同期で) 終える関数を `text/` が公開する
- 本文の編集中 (`editingTextId`) のテキストは、文書の層では描かない (入力欄と二重に見えるため)。選択の重ね描きは、編集中のノードにリサイズハンドルを出さない

### 4.8 画像と SVG の取込

- ファイル選択 (`plugin-dialog`) と OS からのドロップで受け取り、path を既存の `vector_read_image` / `vector_read_file` に渡す。検証は Rust が行う
- 置く位置は、表示範囲の中央か、ドロップした位置。大きすぎる画像は表示範囲に収まる大きさに縮める (アセットは元のまま)
- SVG ファイルは埋め込み SVG として置く。draw.io の SVG の変換と `notices` の表示は今のまま使う
- 取り込む前に、TypeScript 側の `validateSvg` でも文字を抽出し、Rust が返した `text` と一致することを確かめる。違えば取り込まず、理由を表示する (U+0085 をそのまま含む SVG は Rust とブラウザで抽出が違い、置いても保存できないため)

### 4.9 書き出し

- 対象は、選択中の frame やノード、選択がなければページ全体。frame が複数なら 1 つずつファイルにする
- SVG は `SvgEl` を文字列にしたもの。PNG は、その SVG を画像として読み込んで canvas に描く (`src/modules/mermaid/mermaidExporter.ts` と同じ経路)
- PNG の上限は今と同じ (20 MiB、1 辺 16,384 px、16,777,216 画素)。倍率は 1・2・3
- ファイルへの書き込みは注入された関数を通す。切替 PR で `vector_write_file` につなぐ。関数は `export/` の中の登録口 (モジュールの変数と設定用の関数) に渡す。登録がない間は、書き出しのボタンを無効にする。開発用の画面は、ブラウザのダウンロードで保存する関数を登録する
- 書き出す SVG は自分で作った出力なので、取込用の SVG ポリシーでは検証しない (埋め込み SVG を `data:image/svg+xml` で持つため)。UTF-8 と大きさだけを確かめる。この変更は切替 PR で入れる
- 埋め込み SVG を含む文書の PNG 書き出しが WKWebView と WebView2 で正しく出るかは、実アプリで確かめる
- 選択が frame だけなら frame ごとに 1 ファイル。frame でないノードを含む選択は全体を 1 ファイル。frame とその中の frame を両方選んだら、外側の 1 ファイルだけにする。非表示のノード (祖先が非表示のものを含む) は書き出さず、書き出し方の判定にも数えない
- frame の範囲は frame の矩形ちょうど (書き出す画像の大きさを frame の大きさと一致させる。線の外側半分は入らない)。それ以外は、影や線の太さを含めた描画の範囲を外側へ整数に丸める
- 入れ子のノードを選んで書き出すときは、位置だけを合わせる。祖先の切り抜きと不透明度は反映しない
- SVG の上限は 28 MiB (埋め込み SVG と画像は base64 で 4/3 倍になる。20 MiB の埋め込み SVG を持つ文書も書き出せる大きさ)。PNG を作る途中の SVG には大きさの上限を当てず、PNG の上限だけを確かめる
- ファイル名の候補は frame・ノード・ページの名前から作る。NFC にそろえ、ファイル名に使えない文字と Windows の予約名を置き換え、同じ書き出しの中で重なれば番号を付ける

### 4.10 コピーと貼り付け

- クリップボードはエディタの中だけで持ち、別の作品へも貼れる。子孫と必要なアセットごと運び、貼るたびに新しい ID を振る
- 貼り付け先は次の順で決める
  1. frame を 1 つだけ選んでいて、それがコピーしたノード自身でなければ、その frame の中
  2. コピー元の親が今の文書にあれば、その親 (コピー元の兄弟になる)
  3. スコープがあればその中、なければページ直下
- 位置は元のページ座標から右下へ 10 px ずらし、続けて貼るたびにさらに 10 px ずらす。貼り付け先の frame の矩形と重ならない位置になるときは、frame の中央に置く
- 複製 (Cmd/Ctrl+D、Alt を押しながらのドラッグ) は、元と同じ親の、元のすぐ前面に入れる。ドラッグでの複製は開始時に 1 回だけ行い、ドラッグの間は同じ複製を動かす

## 5. 画面

### 5.1 配置

```
┌ 作品バー: [作品 ▼] [新規] [取込] タイトル タグ ……… 未保存 [書き出し] [保存 ⌘S] ┐
├──────────┬──────────────────────────────────┬──────────────┤
│ レイヤー │ ルーラー                          │ プロパティ   │
│          │ キャンバス                        │              │
│          │        ( ツールバー: 下中央 )     │              │
└──────────┴──────────────────────────────────┴──────────────┘
```

- 作品バーは今の `VectorWorkspacePage` のものを引き継ぐ (作品の切替、新規、取込、タイトル、タグ、未保存の表示、保存、削除)。ボタンは「アイコン＋短い名称」(`ui-design.md` v1.15)
- レイヤーパネルは幅 220 px、プロパティパネルは幅 240 px。レイヤーパネルは Alt/Option+1 で開閉する
- ツールバーはキャンバスの下中央に浮かせる。並びは 選択、フレーム、矩形、楕円、線、テキスト、画像、手のひら、倍率
- 色とトークンは `ui-design.md` §2 に従う。キャンバスの地は `--bg-muted` にする (ダークでは `--bg` より暗い面がないため、ライトとダークで同じトークンを使う)

### 5.2 レイヤーパネル

- 前面のノードを上に並べる。frame と group は開閉できる
- 行: 種別のアイコン、名前、表示の切替、ロックの切替。ダブルクリックで名前を変える
- 並べ替えと親の付け替えは `@dnd-kit` のポインター操作で行う。兄弟の最背面 (開いている frame / group のさらに背面) を含め、どの位置へも動かせること。ドラッグの途中で一覧がスクロールしても、落とす位置の判定がずれないこと
- 行の数が数千になっても、ノード 1 個の追加・削除・開閉や選択の変更で全行を描き直さない
- 行のクリックは選択 (Shift / Cmd で複数)。キャンバスの選択と同期する

### 5.3 プロパティパネル

選択に応じて節を出す。複数選択で値が違う欄は「混在」と表示する。

入力欄の確定の規則:

- 確定は、入力を始めた時点で選んでいたノードに当てる。入力の途中で選択が変わっても、新しい選択には当てない。対象のノードがなくなっていたら捨てる
- 何も打っていなければ、フォーカスが外れても確定しない (前のノードの値を別のノードに書き込まない)。入力の途中で Undo などにより値が変わった場合も、打っていなければ何もしない
- 確定 1 回が履歴 1 件。値が変わらない確定は履歴も `revision` も増やさない
- 色の選択 (`<input type="color">`) は、続けて動かしている間をまとめて履歴 1 件にする。`change` が閉じたときにだけ来るとは限らない (WebKit は色を選ぶたびに出す) ので、最後の入力から一定時間 (0.5 秒ほど) 何もなければ確定する形にする
- 整列と等間隔を含め、結果の座標や大きさが §3.5 の範囲を超える操作は当てない

| 節 | 対象 | 欄 |
|---|---|---|
| 整列 | 2 個以上、または frame の中の 1 個 | 左・中央・右・上・中央・下、横と縦の等間隔 |
| 位置と大きさ | すべて | X、Y、W、H (線は始点と終点) |
| 見た目 | すべて | 不透明度、角丸 (frame・矩形・画像) |
| 塗り | frame、矩形、楕円、テキスト | なし / 単色 / 線形 / 円形、色、不透明度、停止点、向き |
| 線 | frame、矩形、楕円、線 | 色、不透明度、太さ |
| 影 | frame、矩形、楕円、テキスト、画像 | X、Y、ぼかし、色、不透明度 |
| 文字 | テキスト | フォント、サイズ、太さ、斜体、行の高さ、字間、揃え、大きさの決め方 |
| フレーム | frame | プリセット、はみ出しを切り抜く |
| 書き出し | すべて (選択なしはページ) | 形式、倍率、書き出し |

何も選んでいないときは、ページの設定 (ルーラー、グリッド、グリッドの間隔、グリッドへのスナップ) を出す。

### 5.4 ショートカット

グローバルの割当 (`ui-design.md` §8.1) と重ならないようにする。Cmd/Ctrl+1〜6 はモジュール切替、Cmd/Ctrl+\ と Cmd/Ctrl+B はサイドバーなので使わない。入力欄にフォーカスがある間は、文字キーのショートカットを効かせない。

| キー | 動作 |
|---|---|
| `V` `F` `R` `O` `L` `T` `H` | 選択、フレーム、矩形、楕円、線、テキスト、手のひら |
| `Space` を押している間 | 手のひら |
| ホイール / `Shift` + ホイール | 縦 / 横にスクロール |
| `Cmd/Ctrl` + ホイール、ピンチ | ポインターの位置を中心にズーム。ピンチは、Chromium (WebView2) では ctrl 付きの wheel、WKWebView では gesture イベントで届くので、両方を受ける |
| `Cmd/Ctrl` + `+` / `-` | ズームイン / ズームアウト |
| `Shift+0` / `Shift+1` / `Shift+2` | 100% / 全体を表示 / 選択範囲を表示 |
| `Cmd/Ctrl+Z` / `Shift+Cmd/Ctrl+Z` | Undo / Redo |
| `Cmd/Ctrl+C` / `X` / `V` / `D` | コピー / 切り取り / 貼り付け / 複製 |
| `Cmd/Ctrl+A` | スコープの中をすべて選択 |
| `Delete` / `Backspace` | 削除 |
| 矢印 / `Shift` + 矢印 | 1 px / 10 px 移動 |
| `Cmd/Ctrl+G` / `Shift+Cmd/Ctrl+G` | グループ化 / 解除 |
| `Cmd/Ctrl+]` / `Cmd/Ctrl+[` | 1 つ前面へ / 1 つ背面へ |
| `]` / `[` | 最前面へ / 最背面へ |
| `Enter` | テキストなら本文の編集、frame / group なら中に入る |
| `Esc` | 操作の取消 → 本文の編集の終了 → スコープを 1 段外へ → 選択の解除 |
| `Shift+R` | ルーラーの表示を切り替える |
| `Cmd/Ctrl+'` | グリッドの表示を切り替える |
| `Alt/Option+1` | レイヤーパネルを開閉する |
| `Cmd/Ctrl+S` / `Cmd/Ctrl+N` | 保存 / 新規 (今と同じ) |

編集のショートカットのうち、押しっぱなしの繰り返しを受けるのは、矢印と Undo / Redo だけ。

### 5.5 グリッド

### 6.1 どのセッションにも共通の規則

- `main` から切った worktree で作業し、§4.1 の自分の担当だけを触る
- 新しい実行時の依存 (npm、crate) を足さない。必要だと考えたら足さずに報告する
- 新しいコードを画面 (`src/modules/registry.ts`、`VectorWorkspacePage.tsx`) とストレージ (`current_payload_version`) につながない
- 切替までは、Rust の新しいコードがテストからしか呼ばれない。未使用の警告は、切替 PR で外すことをコメントに書いた `allow` で抑える
- テストは純関数を中心に書く。DOM を使うものは既存の vitest (jsdom) で書く
- macOS 12 の WKWebView (Safari 15 相当) で動く構文と API だけを使う (`requirements.md` §3.2)。正規表現の後読み (`(?<=…)` `(?<!…)`) は Safari 16.4 からなので使わない。読み込み時に例外になり、キャンバスが開かなくなる
- PR の前に `npm run typecheck`、`npm run lint`、`npx vitest run --dir src`、Rust を触ったら `cargo fmt --check`、`cargo clippy`、`cargo test` を通す
- 報告には、作ったもの、確かめた方法、確かめられなかったこと、契約に対する要望を書く
- PR は下書き (draft) で作る。オーケストレーターが検証してから下書きを外す (検証の前の版が自動マージで `main` に入らないようにする)

### 6.2 開発用の画面

切替までは、アプリの画面からエディタを開けない。「描画とビューポート」のセッションが次を作り、以後のセッションと検証はこれを使う。

- リポジトリ直下の `canvas-harness.html` と `src/modules/vector/editor/dev/` (入口と `EditorHarness.tsx`)
- `npm run dev` のあと `http://localhost:1420/canvas-harness.html` で開く。Tauri の IPC は使わず、契約データの `full` を読み込んだエディタを表示する
- `vite build` の入力には入れない (配布物に含めない)。切替 PR で消すかどうかを決める
- 文書は、`fitTextNodes` でテキストの大きさを求め直してから `load` に渡す (切替後の画面と同じ手順)

## 7. 切替 PR でやること

- `VectorWorkspacePage.tsx` を `EditorRoot` と `editorStore` につなぐ (読み込み、保存、未保存の確認、作品の切替、新規、取込、書き出し、削除)
- Rust の `current_payload_version` を 2 にし、`upgrade_payload` と `validate_payload` を v2 へつなぐ。未使用の `allow` を外す
- 保存の処理は、進行中のジェスチャーを確定してから文書を取り出す。読み込みでは、テキストの大きさを求め直してから `load` に渡す
- 作品を開いたときと切り替えたときは、`load` のあとに全体表示 (`zoomToFit`) を呼ぶ (`load` は表示位置を残すため)
- 未保存や削除の確認などのモーダルが開いている間、キャンバスがキーを取らないことを実アプリで確かめる
- `vector_write_file` の SVG の検証を §4.9 のとおりに変える。SVG の上限を 28 MiB に合わせる
- 書き出しの保存先の関数 (`setExportWriter`) を登録する。複数のファイルは、1 つずつ保存ダイアログを出す (権限と Rust を変えずに済み、上書きの確認を OS のダイアログに任せられる)
- 保存、作品の切替、画面を離れる前の未保存の確認は、本文の編集を終えてから行う (§4.7)
- `src/modules/vector/index.ts` の表示名を「キャンバス」にし、検索結果の表示を確かめる
- SVG-Edit 一式を消す: npm の `svgedit`、`prepare:vector`、`test:vector:*`、`predev` / `prebuild` の該当部分、`scripts/svgedit/` の adapter 群、`protocol.rs` と `vector_editor_url` (`registry.rs`、`build.rs`、`permissions/default.toml`)、`bridge.ts`、`third_party/svgedit-NOTICES.txt`、About と `THIRD_PARTY_NOTICES.md` の表記
- SVG ポリシー (`policy.json`、`svg-policy.js`、`svg-policy.d.ts`、`validation-fixtures.json`) を `scripts/svgedit/` から移す
- ドキュメント: ADR-0021 の Status を「Superseded by ADR-0026」にする。`requirements.md`、`ui-design.md` (§5.2、§6.23、§8、改訂履歴)、`data-model.md`、`module-contract.md`、`architecture.md`、`README.md`、`CLAUDE.md`、`docs/vector-editor-verification.md`、スクリーンショットを本書の内容へ書き換える
- 受入: v1 の作品が開けて見た目が残り書き出せる、v1 の `vector` を含む古いエクスポートファイルを取り込める、アプリ / プロジェクト JSON とバックアップが v2 で往復する、portable ZIP が 80,000,000 bytes 以下
